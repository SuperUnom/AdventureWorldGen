# r25：侵蚀、河流及群系规划提速

目标是尽量将各阶段压到 10 秒以内。本轮保留默认地图半径、采样间距、水滴数量、生长规则、随机序列和规划结果，不降低地形精度。**尚未全部达到 10 秒：本机默认种子的河流、成本图和群系分配仍超标。**

## 算法与数据结构

- 侵蚀：一次生成固定径向笔刷，水滴只遍历非零权重；边缘重新归一化，保留权重累加顺序及浮点运算顺序。没有减少水滴或寿命。
- 平滑：以数值键的 16×16 稀疏块保存原高度和滤波修正，消除坐标对象散列冲突，并复用线程最近访问块。两个缓存各最多 32,768 块、64 MiB 的 double 数据，另有索引和数组头开销；每线程可暂留一个已淘汰块。任意小数坐标仍使用原连续地形与原滤波插值。
- 区域与海岸：区域先建立精确近邻距离上界，剪掉无法影响最近两点、200 格地形混合或 48 格配方边缘的远点；保留等距排序和高度累加顺序。海岸利用距离函数的变化上界，跳过已证明完全处于陆侧／海侧混合饱和区的查询；岸线附近仍精确求距。
- 噪声配方：预计算固定 octave 频率、权重及归一化因子；复用 Worley 网格点；共享配方子表达式按原始浮点坐标缓存少量结果。负坐标和原有扰动顺序不变。热点的向下取整改用数值语义相同的 `Math.floor`。
- 河流：候选方向以非负代价下界剪枝；在昂贵的岸高包络前拒绝确定相交的折线；主河水位下限已经决定结果或支流已经必然失败时终止剩余岸高探测。最终水位、河道间距和汇流验证仍完整执行。
- 成本与群系：扩大有上限的精确整数采样缓存；共享有上限的整数／半格地形缓存，小数和对角线分数不量化；群系合法环境检查按群系及精确归属格缓存，生长优先级、搜索次数和所有硬限制不变。
- 填充与过渡：首次发布直接复用已冻结的区域、地形和温湿度对象，避免重新计算同一套温湿度及地形。存档解码仍从持久化状态重建。

公开版本、实现缓存标识和存档格式保持不变；已有 READY 计划可以继续加载。

## 默认种子实测

半径 3000、种子 7331、Java 21、`-Xmx2g`，独立 JVM 开启 JFR profile。每轮使用不存在的世界目录，执行完整规划、有效面积检查和原子存盘。基准结构为固定方块盒，真实原版结构准备由游戏测试另行覆盖。

| 阶段 | 本轮 r24 基线 | r25 | 10 秒目标 |
|---|---:|---:|---|
| 侵蚀 | 17.50 秒 | 5.93 秒 | 达到 |
| 河流 | 48.88 秒 | 11.77 秒 | 未达到 |
| 成本图 | 19.57 秒 | 12.60 秒 | 未达到 |
| 群系分配与生长 | 30.51 秒 | 18.01 秒 | 未达到 |
| 填充与边界过渡 | 22.14 秒 | 4.11 秒 | 达到 |
| 完整规划 | 154.00 秒 | 61.44 秒 | — |

全流程耗时减少约 **60.1%**。这是同机本轮测量，不是不同机器、种子或更大地图的时间保证；历史 r24 记录与本次基线也有负载差异。

阶段检查点观察到的堆占用从约 600 MiB 增至 852 MiB；这不是进程峰值或堆保留量。新增缓存以更多内存换取重复采样减少，均有明确容量上限。

## 验证与复现

完整 `test build --offline` 通过：133 项测试，0 失败、0 跳过。

真实 Minecraft 定向 GameTest **1/1 通过**：默认半径 3000 的首次规划包含原版金字塔准备，耗时 63.97 秒；随后群系地形硬限制、READY 重载以及重载前后群系一致性检查通过。完整用例耗时约 66.9 秒，服务器停止和保存区块另计。

新增旧 r24 JAR 生成的固定输出回归：三个种子各 4,096 个区域样本、凹岸线两侧的 40,401 个完整地形样本，以及 1、2、8 格侵蚀网格的完整浮点增量。另覆盖精确半格缓存、小数旁路、负零、缓存淘汰和多线程平滑查询。

```sh
cd neoforge
GRADLE_USER_HOME=/tmp/forge-gradle-home ./gradlew test build --offline
./gradlew -I tools/planning-benchmark.gradle writePlanningBenchmarkClasspath --offline
java -Xmx2g -cp "$(cat build/planning-benchmark-classpath.txt)" \
  tools/PlanningBenchmark.java \
  src/main/resources/data/adventureworldgen/adventureworldgen/profiles/default.json \
  build/planning-r25-new-world 7331
```

后续瓶颈仍是精确地形采样和顺序竞争生长。本轮没有通过阶段改名、提前挪动工作或减少必需验证满足计时目标。如果每阶段 10 秒是硬要求，还需要明确目标硬件、地图规模，以及是否允许改变地形／群系规划结果后再选择下一种算法。


集成测试沿用定向测试入口，并使用全新世界目录：

```sh
./gradlew runGameTestServer -I tools/r24-gametest.gradle \
  -PterrainAuditWorld=run-r25-planning --offline
```

本机沿用独立测试目录的 `config/fml.toml` 中 `disableConfigWatcher = true`，避免系统 inotify 上限影响测试；生产配置未修改。
