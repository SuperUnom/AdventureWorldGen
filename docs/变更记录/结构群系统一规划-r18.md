# r18：先统一规划必要群系，再放置必要结构

必要结构附带的群系现在直接进入普通必要群系需求列表。所有必要群系先共同完成规划，然后才调用结构适配器，在对应已生成群系内部选址、冻结结构。

- 每个最低数量内的结构实例产生一个独立群系需求，面积、允许 ID 和冒险等级来自结构配置；出生结构即使配置 `count.min=0`，仍按有效最低数量统计一次。
- 同一批需求共同进入温度需求统计、土地容量统计、种子排序与选址、最低面积和目标面积竞争、连通性及混合后的有效面积校验。结构承载需求没有额外面积倍率，也不再走矩形面积分配。
- 多个允许群系是备选关系，按合法土地供给分摊一份温度需求，实际选址在备选群系中比较环境和连通空间。用户同时指定出生群系时，出生结构承载 ID 限定为该群系。
- 必要群系全部生长完毕后，才在结构自己的群系内搜索平坦位置，检查完整占地、保护范围、入口、出生安全、结构间距和冲突。改变结构尺寸不会改变此前的群系布局。
- 每个结构在 16、8、4 方块网格上细化局部候选，最多准备 4,096 次；无法放入时报告实例、群系、地块面积和尝试预算，不覆盖其他群系，也不省略必要实例。
- 默认金字塔附带沙漠移除旧的 16,384～32,768 特殊面积，使用普通必要群系的 `min=32768,target=393216` 默认配置，目标后持续生长。
- 进度增加“必要结构放置”阶段，位于必要群系生长之后。r17 的完整 READY 数据恢复方式保留；算法版本更新后旧计划首次重建，随后直接加载。

可选结构实例仍使用原有的独立尝试策略，本次调整针对必要实例。

## 验证

单元回归新增：适配器不能在群系生长完成前运行；结构尺寸变化不改变已生成群系；备选群系中非法地形项不能阻挡合法项选址；结构附带群系使用自然连通掩码并继续超过目标生长；完整结构放不进去时必须报告失败。

测试地图与面积报告位于 `neoforge/build/reports/biomes-r18/`。图中的白点表示必要群系种子，橙色方框表示随后放置的结构，二者无需重合。独立地图工具使用实际冻结环境与径向软等级评分、测试结构占地；Minecraft GameTest 使用真实适配器和成本图。
