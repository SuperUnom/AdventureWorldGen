# 规划进度、局部海岸与群系过渡 r8

本次对应五项反馈：规划进度不可见、边界毛刺、小尺度海岸与群系边缘过于平滑、河湖没有水域群系，以及群系之间缺少交错过渡。

## 规划进度

单人世界加载界面在规划期间显示中文或英文的阶段名称、阶段总进度、已用秒数。读取规划、大陆海岸、侵蚀、水文、通行成本、群系结构与保存各有阶段区间；侵蚀按已完成批次、成本计算按已处理节点更新。总百分比按阶段权重计量，不是剩余时间预测。联合放置没有固定工作总量，在阶段起点显示当前阶段与持续更新的耗时，不用计时器伪造完成进度。

启动时先异步登记规划任务，让 Minecraft 建立加载界面；群系查询、区块生成和世界加载事件仍保留 READY 等待。只有缓存读取成功或计划原子发布成功才标为 100%。失败保留失败状态，结束服务器时清除显示状态。客户端类仅在客户端注册，专用服务器不加载 GUI 类。

客户端冒烟测试通过 `runPlanningSmokeClient` 自动打开隔离测试世界、捕获规划界面，再验证进入世界后退出。本次先在 `run-planning-smoke/saves/progress-r8` 准备了只有 `level.dat` 的测试存档，并使用伴生测试种子；重新执行时也需准备该测试存档，避免直接复用已有规划而跳过进度界面。截图位于 `neoforge/run-planning-smoke/screenshots/planning-r8.png`，测试代码不打入模组 JAR。

## 边界与过渡

- 原代码先扭曲坐标再向下取整，导致格子不均匀；地表逐方块查询与原版群系四格采样也不一致。现在先统一到世界对齐的四格中心，再以浮点扭曲坐标计算距离。四格内地表群系与实际区块调色板保持一致。
- 坐标扰动分成多次小位移，每一步的最大导数范数小于 1，避免坐标折返。基础尺度为 512、160、64 方块；海岸复合两轮扰动，并在变换前细分到不超过 4 方块的线段，再参与轮廓精度比较。简化容差不超过 0.25 方块，保留局部湾口与岬角。
- 填充群系之间加入由 40 和 128 方块尺度连续噪声控制的过渡带，相邻群系以成片斑块竞争归属。只有距离接近的邻区参与竞争；这是空间相关的斑块，不是逐方块随机撒点。
- 必须群系的边缘也加入连续斑块扰动，核心保持完整。面积统计、重叠检查、结构保护与运行时查询使用同一份四格掩膜。联合规划改为检查实际掩膜重叠，并在搜索候选时一起检查群系兼容性，避免把外接矩形重叠误判为不可放置。

地表方块本身仍是离散格子，因此不会消除 Minecraft 的所有像素阶梯；本次针对的是细长毛刺、失真的扭曲坐标，以及缺少局部形态变化的问题。植被仍由对应群系的原版或模组特征生成。

## 河湖群系

河流和湖泊在底层陆地承载归属上叠加 `minecraft:river`，雪原等已知原版寒冷群系使用 `minecraft:frozen_river`。原版没有独立湖泊群系，因此湖泊使用同样的水域群系。新增河床砾石表层适配，并将两个群系纳入注册表预检。

底层陆地归属继续用于承载面积统计，水域叠加不吞掉配置中已分配的群系面积。模组自定义寒冷群系目前默认使用普通河流，尚未增加通用的模组气候映射规则。

## 复现与产物

用户种子 `345705185492107788` 纳入实际区块回归，检查水域群系确实写入区块，而不只是查询返回标签。此前河岸、原版海洋、结构和确定性回归继续保留。`BoundaryPreview.java` 可从保存的计划生成局部群系及海岸诊断图；图不包含植被，不是客户端实景截图。

实现修订为 `planner-v2-impl-2026-09-08-r8-progress-ecotones-final`。最终分发文件为 `neoforge/build/libs/adventureworldgen-0.1.0-r8.jar`。替换旧 JAR 后新建世界验证；已有区块不会自动重建。

最终验证（2026-09-08）：57 项单元测试、6 项 GameTest 通过，`test runGameTestServer build --offline` 构建成功；实际客户端已捕获中文进度界面并正常进入世界。海岸与过渡带未进行客户端全图巡查。
