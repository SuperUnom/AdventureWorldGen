# r28 温度硬约束与填充配置

## 修复

r27 的温度场已经采用确认的 v7 参数，但群系分配仍将温度作为候选排序：没有合适候选时可退到相邻温度带。统一环境准入只检查湿度和岸线，没有检查温度。这解释了雪坡能够扩张到中温带；本轮没有重新生成完整的 7331 世界。

r28 将 `biomes.terrain_rules.<群系ID>.temperatures` 的键作为硬允许范围，正数权重只决定范围内偏好。统一准入覆盖必要群系、结构承载群系、填充的播种与扩张，以及补洞和查询层边界混合。岸线预留也检查候选海滩的温度，不能让不符合温度的海滩排除正常陆地候选。没有合法供给时报告配置缺口，不通过跨温度带满足面积。

温度场参数和阈值未变。湿度场公式未变。

## 在哪里调整

默认文件：`neoforge/src/main/resources/data/adventureworldgen/adventureworldgen/profiles/default.json`。

`biomes.filler` 只负责列出候选 ID；`terrain_rules` 为同 ID 的必要群系、填充群系和结构承载群系统一提供环境配置。默认填充池每个 ID 都有显式的 `temperatures` 和 `humidities`。

例如默认雪坡的关键配置为：

```json
"minecraft:snowy_slopes": {
  "allowed_terrain": ["plains", "hills", "plateau", "mountains"],
  "landforms": ["foothill", "slope"],
  "temperatures": {"very_cold": 1},
  "humidities": {"dry": 1, "medium": 3, "wet": 2},
  "filler_weight": 3
}
```

这里四类地形兼容复合配方，但 `landforms` 仍要求实际地貌是山脚或山腰；`very_cold` 要求实际温度低于 2.5，权重再大也不能进入中温带。需要允许冷温带时，显式加入 `"cold": 1`。`allowed_templates` 可进一步指定具体地形配方，省略时允许全部配方。

规划器没有按群系 ID 写陆地地形后备表。地形本身的山脚/山腰/山峰分类仍由高度、山脉影响、坡度和局部高差计算；河流/冻河是另一个水体覆盖逻辑，不属于此处的陆地填充配置。

没有温度规则时允许全部温度；仅显式提供旧字段 `temperature_level` 时，仍按旧映射得到单一允许温度类型。规范化配置会保存允许类型，往返读取不丢失含义。

## 默认供给覆盖

- 非常冷：雪原限定低地、雪坡限定山脚/山腰、冰封山峰限定山峰，允许全部配方以覆盖复合地形。
- 冷、温和、炎热：保留常规候选，以权重 0.15 的风袭沙砾丘陵覆盖剩余地形组合。低权重降低其常规竞争概率，并非仅在其他候选不存在时启用。
- 平原允许冷/温和/炎热，权重 1:4:1，适应不再改写温度的固定出生点；仍保留原有地形范围。

这些都是默认 JSON 的选择。自定义配置需要覆盖实际出现的地形、温度、湿度组合。出生群系若不满足原点环境，明确报错，不修改温度场或悄悄忽略配置。

## 验证与使用

仅离线编译、打包和四项定向检查，全部通过（测试执行约 0.54 秒）：

1. 必要群系每个扩张格均满足温度；没有相应温度供给时拒绝跨带回退。
2. 7331 种子的半径 256 合成山地中，填充扩张和查询扭曲均不让雪坡进入中温区；还覆盖邻近存储标签全是雪坡时的查询兜底。
3. 省略温度、显式旧温度字段和配置往返读取语义。
4. 默认填充池的温湿度规则，以及各配方组合、地貌、温度与湿度组合的配置覆盖。

未启动游戏，未跑完整世界生成或完整测试套件。产物为 `neoforge/build/libs/adventureworldgen-0.1.0-r28.jar`。

规划缓存修订更新为 `strict-climate-r28`。建议新建 7331 世界比较；已有区块不会重建，旧世界保存的配置也不会自动替换成新的默认填充配置。
