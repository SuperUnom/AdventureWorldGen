# 数据包与适配器开发

[文档总览](../README.md) · [配置字段](配置说明.md) · [运行时契约](运行时与结构适配.md)

## Profile 覆盖

固定 profile ID 为 `adventureworldgen:default`，资源路径为：

```text
data/adventureworldgen/adventureworldgen/profiles/default.json
```

发行 JAR 自带默认文件。整合包可用一个数据包在相同资源位置覆盖；缺失资源或同时存在多个外部覆盖源会在任何 AdventureWorldGen 区块生成前终止。字段、默认值和交叉校验见[配置说明](配置说明.md)。默认生产 profile 使用半径 3000、出生 `minecraft:plains`、27 条树林与山地必须群系、8 种原版填充群系、按群系配置的地形规则和一个 `minecraft:desert_pyramid`。

## 公开适配注册

其他模组须在构造阶段、首次服务器规划之前调用 `AdapterRegistrations.register(BiomeAdapter)` 或 `AdapterRegistrations.register(StructureAdapter)`。首次预检会冻结注册集合；之后注册会失败，以免加载顺序改变计划哈希。

`BiomeAdapter` 仅提供注册 ID、适配器版本和地形兼容性/软偏好；已移除 `surface(...)` 与 `SurfacePalette`，外部适配器应删除这些实现后重新编译。普通群系不再逐个内置注册，默认使用通用适配器；群系选择与环境限制由 profile 的 `biomes.required`、`biomes.filler`、`biomes.terrain_rules` 和 `spawn.biome` 配置。仅保留海洋、河流和冰冻河流的内置群系适配器及第三方注册入口。当前规划器只读取兼容性结果的 `allowed`，未使用 `softPreference`。所有陆地、河床与湖床统一执行注册的 `minecraft:overworld` 地表规则，本模组不再选择或覆写表层材料。第三方群系需将专属规则接入这一主世界表面生成流程；仅注册群系、或只在专用 ChunkGenerator 内实现表面逻辑，不代表该逻辑会自动执行。

`StructureAdapter` 只负责**冻结**：在规划期固定合法旋转、每个部件的 NBT、物理占地、群系保护范围和入口，并验证支撑；不能完整冻结的内容返回 `UNSUPPORTED_CONTENT`。适配器不放置方块，也没有逐区块提交入口——注入之后由原版 `StructureStart` 流水线落块。

部件类型必须由内容方注册到游戏的部件注册表（本工程的原版实现见 `compat/vanilla`，伴生示例见 `src/testmod` 的 `WaystationPiece`）。恢复时按冻结 NBT 里的 `id` 查到类型并交给该类型重建，因此核心生成器不需要为新结构增加分支。规划在**发布 READY 之前**与**解码 READY 之后**各检查一次全部冻结部件：环境没有注册该类型时以 `UNSUPPORTED_CONTENT`、阶段 `structure-piece-restore` 失败，诊断含 `structure_id`、`instance_id`、`piece_id`、`piece_type`，并保证不产生（或改写）READY。给出这个答案的是 `api.FrozenPieceSupport`，它属于运行时能力，不进入计划输入身份。

基础地形高度、河湖水位和群系位置仍由规划器决定，原版地表流程使用对应高度与群系信息。允许原版地表阶段生成恶地柱体等表面构造，因此最终表面可能高于规划基础高度；不再替换恶地群系来抑制柱体，也不再追加河湖床沉积物处理。植被等群系装饰继续走宿主装饰流程。

`src/testmod` 是独立伴生实例：注册 `testcompanion:ashen_grove`、两部件 `testcompanion:waystation` 与自定义部件类型 `testcompanion:waystation_piece`。它验证适配器查询/植被、冻结与 READY 重载一致、恢复为自定义类型、起点注入与原生候选抑制；地表集成测试另外验证原版材料、规划高度和群系归属。该 source set 不进入生产 JAR。

同一伴生实例还提供普通世界端到端审计（`testcompanion.WaystationAudit`，由系统属性启用，见 [重构实施记录 §10](重构/重构实施记录.md#reproduce)）：冷启动规划并生成受控结构涉及的全部区块、READY 重启后逐项对照，覆盖跨区块引用、真实 `postProcess` 落块、容器战利品与种子持久化以及原生候选抑制。

## 失败诊断

`PlanningFailure` 的稳定类别为 `CONFIG_CONFLICT`、`UNSUPPORTED_CONTENT`、`RESOURCE_LIMIT`、`SEARCH_BUDGET_EXHAUSTED`、`PRECISION_INSUFFICIENT`、`NO_SOLUTION_IN_DOMAIN` 与 `EXECUTION_FAILED`。日志同时提供阶段和稳定排序的诊断字段。不要删除失败后的临时目录来“修复”世界；加载器不会读取未发布目录，下次启动会按同一输入安全重试。

## 专用服务器

安装生产 JAR 后创建新的普通世界即可自动启用；已有世界、超平坦、调试世界、下界和末地不变。首次启动会在服务器进入区块生成前等待完整规划，后续启动直接校验并加载 READY 计划。数据包或适配器版本改变会产生新的输入哈希并重新规划；v1 不承诺旧配置迁移。
