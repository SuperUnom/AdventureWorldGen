# r27：接入已确认的第七版温度场

新生成计划采用[第七版预览](双场温度带-实验预览.md)的二维温度场与海拔温差。正式 `ClimatePlan` 和预览工具复用 `OrganicTemperatureField`，保留原预览的噪声键，避免代码移植改变种子对应的分布。

## 固定参数与行为

- 主特征尺度 450 格，二维扭曲幅度 450 格、尺度 1150 格；次级扭曲幅度 99 格、尺度 483 格。
- 基础温度 `5 + 0.6 × (形状温度 - 5) + 2.0`。形状温度采用两层梯度噪声及 tanh，与第七版一致。
- 有效高度为 25% 实际地面、55% 坡面平滑高度、20% 山体平滑高度。Y76–110 每百格降温 1.2，Y110 以上每百格降温 6.5；两个场叠加后限制到 0–10。
- 四档阈值固定为 2.5、5、7.5，不再按需求面积校准阈值、旋转方向、修改出生核心温度或增加局部需求修正。
- 温度需求面积仍保留为诊断信息。群系继续优先选择配置中的温度类型，不足时按既有相邻温度回退；温度不再为需求反向修改。有限地图不保证每档均出现，也不保证每座低山有三个温度层次。

`HumidityPlan` 的代码和参数均未修改；其原有蒸发项会读取新温度，因此湿度结果可以随温度变化。原版降雪、结冰机制和群系硬地形约束未改动。

## 存档与游戏接入

游戏现有调用链 `RuntimePlanner → JointPlanner/ClimatePlan → GeneratedAdventurePlan → AdventureBiomeSource` 使用新温度来规划群系。存档的气候状态增加 `temperatureField: "organic-temperature-v7"`，保存平滑高度场和固定阈值。重载恢复高度数据，不重新采样地形来规划温度。

缺少版本字段的历史状态继续按原有温度公式解码；未知版本和被修改的新阈值会拒绝加载。内部缓存修订已更新，因此正常升级后的旧 READY 指纹不命中，会重新规划。**已生成区块不会随新计划重建，建议用新世界测试。** 同一种子若使用了不同版本的地形或配置，温度图也可能随海拔变化；第七版预览使用的是 r25 保存的地形。

## 本轮验证范围

按用户要求只做编译、打包及三项小范围测试（3/3 通过，测试耗时约 0.13 秒）：

1. 第七版保存数据中的八个温度样本，误差在 float 输出对应的 1e-6 范围内。
2. 正式温度包含出生点在内与固定公式一致；JSON 状态重载无需采样地形，温度及湿度查询一致。
3. 旧状态仍按旧版本恢复，未知版本与篡改后的新阈值被拒绝。
