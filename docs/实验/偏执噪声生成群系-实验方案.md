# 偏执噪声生成群系：多维噪声匹配与必要偏置

状态：待实施方案，按用户最新说明修订。实验分支：`experiment/偏执噪声生成群系`；基线：`main` 的 `2f032f0`。分支及文件保留原名称，技术正文使用“偏置噪声”。

核心约定：**使用类似原版的多维参数空间最近匹配生成全部群系，只为必要需求增加局部偏置噪声，使其在适宜位置出现。** 规划阶段调整的是偏置场参数，运行时的每个群系仍由同一个多维匹配函数得到。

## 1. 原版参考与本项目的对应关系

已核对本地 NeoForge 开发依赖中的 `Climate.Parameter.distance`、`Climate.ParameterPoint.fitness`、`Climate.ParameterList.findValue` 和 `MultiNoiseBiomeSource.getNoiseBiome`：坐标先采样为共享参数向量，再比较该向量与各群系参数区间的距离，选择距离最小的条目。原版参数包括 temperature、humidity、continentalness、erosion、depth、weirdness。

公开映射文档也描述了“选择最近参数区间”的机制：[Fabric Yarn MultiNoiseUtil.NoiseHypercube](https://maven.fabricmc.net/docs/yarn-1.21.5-pre3%2Bbuild.1/net/minecraft/world/biome/source/util/MultiNoiseUtil.NoiseHypercube.html)。该链接用于解释机制；本工程接入以本地目标版本源码为准。

本项目采用这一匹配方法，参数轴结合现有地形系统设置。温度、湿度来自共享连续场；高度、到达难度读取真实规划数据；增加共享变化噪声区分环境相近的群系。不会为每一种普通群系生成一张独立随机得分图。

新增偏置是位置相关的匹配距离减项。它不是原版配置中的常量 `offset`：本地源码中该常量以平方项加入距离，不能通过设置负值来获得负距离奖励。

## 2. 基础多维群系划分

首版采样向量：

```text
Q(x,z) = [T, M, H, D, V]
```

| 参数 | 来源 | 含义 |
|---|---|---|
| T：温度 | 大尺度趋势、连续噪声、多尺度海拔降温 | 冷暖分布 |
| M：湿度 | 独立连续噪声、海洋及河湖影响；可加入平滑迎背风修正 | 干湿分布 |
| H：高度 | 最终地形地表高度，统一归一化 | 低地、山地、高山 |
| D：到达难度 | 从实际规划出生点出发的最小累计通行成本 | 冒险等级倾向 |
| V：变化 | 一张全域共享的低频变化噪声 | 同类环境中的不同群系变体 |

所有群系查询同一组场；各噪声通道使用固定种子派生规则。H、D 参与匹配但不是额外随机生成的场。坡度、地形类别、水域与适配器要求先做合法性筛选，后续需要时再扩展参数轴。

D 沿用 `10 × C / C_coast` 的真实成本语义，不能由到世界中心的直线距离替代。重选出生位置必须重建成本图。不可达与海岸参考成本缺失显式记录，按现有可达性约束及明确的软回退处理，不能跨障碍插值。

地形先冻结，再生成温湿度与成本。T 保留海拔降温；M 中河湖影响局部衰减。偏置不会改变地面高度、实际通行成本或水体。

每个群系 b 配置一个或多个参数区间盒 R。单轴距离和总匹配距离为：

```text
d(q,[lo,hi]) = max(lo−q, 0, q−hi)
F_b(Q) = min over R of Σ_i wi · d(Qi,Ri)²
biome(x,z) = argmin over legal b of F_b(Q(x,z))
```

同一群系可占多个参数区间，用于表达冷暖两类适宜环境等情况。各轴先统一量纲，D 的权重较低以保留软等级语义。首版使用明确的区间距离；旧版不对称等级惩罚不直接塞入普通欧氏索引，若后续保留须单独定义距离和正确的搜索下界。

参数表需要完整覆盖可用陆地，并让同类群系在 V 上有可区分的范围。所有维度完全相同的条目会产生固定同分，不能用随机遍历顺序掩盖。匹配同分按规范化条目顺序确定，索引查询必须与穷举一致。

## 3. 必要群系偏置噪声

每条必要需求 p 保留独立 ID、目标群系 b、等级、面积和一个局部锚点。该条目使用相应群系的参数区间；D 区间来自该条需求自己的等级。普通自然出现使用群系的默认等级偏好，没有配置时 D 不贡献惩罚。

```text
F_p(x,z) = F_parameters(p)(Q(x,z)) − B_p(x,z)

B_p(x,z) = a_p · K(rho_p(x,z)) · (1 + eta · N_p(x,z))
K(t) = (1−t²)²，0 ≤ t < 1；其他位置为 0
0 ≤ eta < 1
```

- `a_p` 控制偏置强度；`N_p` 是低频连续噪声，限制到 `[-1,1]`，因此偏置不会随机反向。
- `rho_p` 是到锚点的归一化距离，可通过平滑坐标扭曲和方向拉伸塑形；在锚点处校正扭曲位移为零。影响范围由半径参数控制。
- 偏置在支撑范围边缘平滑归零，远处完全回到基础多维匹配。首版不使用逐格距离洪泛来决定群系边界。
- 偏置只对对应必要条目起作用；同位置仍比较所有合法自然候选与受影响的必要候选。
- 必要候选仅在自己的局部支撑范围参与，范围外没有必要所有权；其群系若允许自然出现，仍可通过普通参数条目出现。

最终只有一个查询规则：

```text
winner = argmin(普通条目的多维距离,
                覆盖当前位置的必要条目的多维距离 − 局部偏置)
返回 winner.biome_id，并保留 winner.patch_id（如果有）
```

“必要/填充”表示是否带有出现保证，二者使用相同的参数匹配机制。必要偏置只改变局部决策面，不直接写入群系 ID。

对于适宜性已接近的地方，小幅偏置即可让目标出现；偏置强度设上限，并优先选择基础距离小、与竞争者差距小的位置。强度耗尽时重选锚点或报告失败，避免依靠巨大偏置在极不适宜处制造孤立群系。

## 4. 怎样让必要群系确实出现

随机偏置只能增加出现概率。要保留项目现有的最低面积和连通性保证，需要在发布前校准偏置参数，并检验实际查询结果。

```text
生成基础多维场与参数表
  → 查找每条需求的适宜位置和合法空间
  → 设置偏置锚点、幅度、半径、扭曲参数
  → 调用最终匹配函数采样
  → 检查必要面积、连通性、保护范围及相互影响
  → 有预算地调整偏置参数，再采样
  → 满足全部硬条件后冻结发布
```

调整变量限定为锚点、幅度、半径、有限的形状参数。面积不足尝试增强或扩展偏置；超上限尝试减弱或收缩；被河流或硬地形切断则调整形状或更换位置。始终重新检查受影响的其他必要条目，不能假定多个偏置叠加后互不影响。

幅度增加在其他输入固定时可以使对应条目更容易胜出，但面积量化、同分、多个需求轮流调整及连通性使整体求解不保证单调收敛。采用有预算的确定性搜索，保存合法检查点，失败输出缺额、竞争需求和已耗预算。

不通过生长前沿、单元转让、标签平滑或手工补丁修复地图。连通分量算法仅用于检查；不把检查发现的碎片直接改成别的群系。修改后的地图必须能由冻结多维场和偏置参数重新查询得到。

每片必要所有权在最终 4×4 单元上独立统计，单元贡献 16 平方方块，要求包含锚点且四邻接连通，满足 `[min,max]`，在可行范围内追求 `target`。海洋、河湖、危险及硬规则不合法的单元不抵扣陆地配额。

不同必要条目即使同 ID 也不重复计算同一单元；同 ID 的普通出现不自动抵扣必要面积。自然群系可视觉相连，需求所有权仍由同一次匹配中的胜出条目决定。若出现脱离核心的必要所有权小片，调整偏置重新生成或失败，不能仅在统计时把它隐藏。

出生和结构保护也是对最终查询的约束：相关位置必须由兼容且正确归属的条目胜出。保护不满足时调整局部偏置或回退结构选址；不给运行时添加覆盖匹配结果的硬涂色掩码。通过验证后冻结相关输入，后续可选结构加入不得破坏已满足条件。

## 5. 自然过渡怎样产生

基础温湿度场连续变化，群系参数表在相邻的参数范围中安排生态接近的群系。局部偏置由中心向外平滑衰减，必要群系最终与周围自然群系使用同一套距离匹配交界。

例如在整合包有对应群系时，可以把干热到湿热的参数区间依次分配给沙漠、稀树草原、林地、湿润森林；把温度和高度的变化映射为温带林地、冷凉林地、高山植被或积雪。这些序列由参数表和场的实际路径产生，不能在地图生成后另画过渡环。

连续噪声和偏置不会自动保证中间群系存在：参数表必须给中间群系真正能胜出的范围；偏置过强也可能跨过它们。因此验收要检查参数空间邻接关系、偏置幅度和最终边界两侧的生态差异。缺少合法中间群系时给出配置诊断，不凭空注册新群系。

首版关闭额外的 `LocalBiomeBlend` 标签混合，直接检查多维匹配本身的自然度。需要更细边缘时，优先调整共享场的细节尺度与连续采样。任何后续增强都必须进入统一采样公式，并重新验证所有硬条件。

过渡宽度取决于参数区间宽度、环境梯度和偏置衰减，不设置每片固定宽度的过渡圈。保留 Minecraft quart 存储精度，地表与群系查询使用同一结果。

## 6. 代码接入与配置

当前 `AdventureBiomeSource.getNoiseBiome` 通过 `RuntimePlanRegistry` 调用计划查询，传入的 `Climate.Sampler` 尚未用于选择群系。`ClimatePlan` 已有温度，高度与成本模块可以复用；湿度、统一参数表和偏置层需新增。

| 模块 | 拟承担职责 |
|---|---|
| `MultiNoiseEnvironment` | 共享 T/M/H/D/V 采样，固定归一化和噪声版本 |
| `BiomeParameterTable` | 参数区间条目、多区间群系、稳定排序与匹配 |
| `RequiredBiomeBiasField` | 按需求查询局部偏置噪声和支撑范围 |
| `RequiredBiasCalibrator` | 搜索偏置参数，验证面积、连通性和承载 |
| `GeneratedAdventurePlan` | 保存冻结场、参数表、偏置，执行唯一最终匹配 |
| `PlanV2Codec` / 配置规范化 | 新数据编解码、配置哈希及算法版本更新 |
| 审计工具 | 导出基础地图、偏置图、最终地图、环境图与约束统计 |

实验模式建议为 `biomes.layout = "multi_noise_biased_v1"`，旧版保留为对照。新字段尚未实现。实验路径停用 `BiomeAllocationPlanner` 的标签生长、`FillerLayout` 的独立填充布局和查询后的标签修补。

参数表为自然群系与必要候选提供共同生态参数。温度配置转换为区间，补齐湿度和 V 分布；硬高度与软高度保持独立。旧 `filler_weight` 的概率语义不能直接等同距离减项，实验首版用显式参数区间定义常见程度，并对尚未支持的权重发出配置诊断。

本项目的轴及硬筛选需要自定义匹配器，不能把 H、D 偷换进原版不同语义的字段。首版用穷举作为正确性基准；后续索引需要支持硬合法性过滤，并分别查询普通参数条目和所有覆盖当前位置的必要偏置条目。查最近普通条目后只给它加偏置会漏掉正确赢家。

偏置支撑范围使用空间索引；局部修改只重采样受影响区域。环境缓存可以采用粗网格，但最终面积和保护必须调用真实 quart 查询函数。最终查询完全由冻结数据决定；派生所有权缓存只加速查询，不允许包含无法从公式重建的标签修补。

## 7. 实施顺序与验收

1. 接通 T/M/H/D/V 和参数区间表，生成无偏置的基础群系图，验证真实成本接入与生态参数分布。
2. 添加单个必要群系偏置，输出幅度、范围、最终连通面积的变化图，确认支撑范围外基础查询逐点不变。
3. 加入多需求校准、重复 ID、出生与结构约束。有限搜索不足时明确失败，不发布未满足最低需求的世界。
4. 接通持久化、实际区块与地表查询，验证重载和不同区块生成顺序结果一致。
5. 与 `main` 基线在相同地形和种子下对照自然度、必要保证、规划耗时与峰值内存。

硬验收包括：每条必要需求达到合法面积范围、最终所有权单一四邻接连通、无硬地形违规、出生与结构承载成立、所有陆地有合法结果、冻结公式重建与缓存逐点一致。偏置全零时结果等于基础匹配；支撑范围外不变；索引与穷举一致。

自然度记录生态跳变边界长度、小碎片面积、必要区域轮廓、参数空间过渡序列与冒险等级分布。到达难度保持软偏好，不承诺每条探索路线严格按等级排序。

使用四个已有固定种子 `1`、`7331`、`345705185492107788`、`4126649097427443736`，再增加至少 16 个固定种子及稀缺高山、河流割裂、重复必要 ID、相互争地、同分参数盒、缺少过渡群系等针对性配置。调参集和验收集分开。

现有文档中硬等级、内陆水域计数有历史冲突；此方案沿用 `配置说明.md` 与 r16 的软等级、有效干燥陆地面积语义，实施时同步修订相关旧定义。

本次只修订方案，尚未修改生成算法或执行构建验收。
