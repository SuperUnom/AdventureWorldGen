# 群系规划器改造方案：容量分配与温度软约束

> r16 更新：群系位置、最低／目标面积、连续温度带、生长与查询混合以[需求温度带与竞争生长](../变更记录/需求温度带与竞争生长-r16.md)及[当前配置说明](../配置说明.md)为准。下文涉及旧群系算法的描述保留作历史背景，结构与成本部分仍适用。

状态：本文保留基于 r11 的设计方案；索引、联合面积分配、容量预留、温度软约束和诊断已接入 r12，实际行为及保证边界见 [r12 实现说明](../变更记录/联合面积与温度规划-r12.md)。冒险等级语义仍为现行硬约束。

## 用户目标

- 降低规划耗时，减少因群系落位而失败；地形只生成一次，避免失败后反复修改山体、海岸和河流。
- 每个群系可配置温度等级，相邻群系的温度尽可能接近。温度是软约束，不能导致合法世界规划失败。
- 保留必须群系、面积、出生安全及群系的地形兼容限制，继续形成自然边界和斑块交错过渡。

## 与 r11 衔接

[r11](../变更记录/规划崩溃修复-r11.md) 修复了成本细化窗口、出生点虚假绕路、出生区域预留过晚及出生地块无法避让禁用地形的问题。崩溃种子 `4126649097427443736` 完成规划约需 123 秒，这个时间包含海岸、侵蚀、水文、成本图和落位，不能全部归因于群系搜索。

当前 `JointPlanner.findCenter` 单次最多准备 2,000,000 个候选，合法候选还要验证固定地块掩码的面积、兼容性和重叠情况。后续改造重点是用可复用的合法区域索引和联合面积分配替换这条搜索路径。

保留 r11 的成本计算修复、优先处理出生需求、完整单元验证与失败诊断。r9/r10 的分形海岸、相关噪声和斑块交错目标继续保留；新的地块归属表示将替代当前仅保存边框、按固定公式重建掩码的方式。

## 成功保证适用范围

任意固定随机地形与任意硬约束组合不一定存在解。总面积足够，也不能证明不同需求共享的合法区域足够，更不能单独证明严格连通、固定冒险等级和复杂结构都可满足。

建议分两层建立保证：

1. **面积分配保证：** 在最终地形的真实合法单元上，构造满足所有最低配额、上限、互斥占用及兼容性限制的分配证书。确定性分配算法应能返回这个有限模型内的可行结果；后续软优化始终保留它。
2. **默认配置的构造保证：** 宏观容量预留与地形生成器之间建立契约，使预留区域在侵蚀、水文和最终模板分类后仍满足其承诺。还需覆盖出生、等级和结构条件，才能把保证扩大为整个默认规划流程的成功保证。

第二层尚需设计和验证，不能仅凭容量表或多种子测试宣布已经完成。自定义配置应尽早检查冲突；固定地形生成后才可判断的冲突，应在建立索引后报告具体缺口。有限搜索耗尽与已证明无解必须使用不同诊断。

## 建议流程

### 1. 联合预留容量

根据必须群系、出生需求和结构承载需求，计算最低面积及共享的允许地形、海拔条件。对共同竞争的合法区域联合预留，避免同一块低地被重复承诺给多个群系。

预留带余量的平原、丘陵、高原、山地区域及受海拔约束的低地。出生需求优先保留安全容量；结构需要自己的足迹、保护范围、入口和地形可行性证明。

预留以区域和容量约束为输入，不直接把宏观区域边界画成最终群系边界。地形生成一次后冻结；侵蚀、水文、岸线与模板混合必须遵守明确的预留契约。仅在侵蚀前贴上“山地”或“低地”标签不能保证最终容量。

### 2. 建立最终合法区域索引

统一索引地形模板、地面高度、水体、危险区域、到达成本、允许群系及结构保护范围。同一最终单元的地形查询与兼容性判断复用缓存。

先在 16 格尺度聚合完全合法的单元，混合地形及边界区域细化到 8 格和 4 格。粗单元只有在组成它的最终单元全部满足对应硬约束时，才能把整块容量计入该需求；否则保留细粒度信息。不能以粗采样替代最终面积及地形验证。

索引直接提供合法候选和可用容量，避免在整片大陆上反复随机试放，再重新扫描完整掩码。

### 3. 同时分配所有最低面积

使用容量分配或流模型处理不同需求对同一合法区域的竞争：每个需求有最低配额和上限，每个最终单元最多有一个占用归属，需求只能获得兼容的单元。结构冻结后的保护区域和出生保留区域先进入模型。

模型必须给出可检查的分配结果；失败时报告哪些需求争用哪些区域、还差多少合法面积，而不是只报告“随机候选耗尽”。

群系沿合法的山坡、山脊和河谷扩展，形状适应地形。主体连贯和紧凑作为优化目标，边缘允许附属斑块、嵌入与空隙。若以后要求严格单连通，需另外提供约束求解或可构造证明，普通容量分配无法直接给出这个保证。

### 4. 填充与有限软优化

首先保留满足全部硬约束的结果，再填充剩余区域，并按确定性次序和固定操作预算改善形状、温度邻接及边界。一次交换需要联合检查所有受影响需求；只提交仍满足硬约束的修改。

优化预算耗尽时直接返回已经验证的合法结果。不能把“温度不够接近”或“形状不够美观”当作重新生成地形、丢弃必须群系或规划失败的理由。

斑块交错使用空间相关噪声和一定宽度的过渡区域，避免逐格独立随机产生椒盐噪点。最终归属必须持久化，规划面积、边界交换与运行时群系查询使用同一结果。

## 约束分层

| 条件 | 后续设计的处理方式 |
| --- | --- |
| 必须群系、面积下限与上限 | 硬约束，联合分配和每次修改后检查 |
| 地形模板、海拔限制 | 硬约束，对真实最终单元验证 |
| 出生安全、指定出生群系 | 硬约束，先预留并验证 |
| 结构数量、足迹、入口、保护与间距 | 保留现行硬约束，单独建立可行性处理 |
| 当前固定冒险等级 | 继续按现行硬约束处理；语义变更待定 |
| 温度接近、紧凑、主体连贯、邻接自然 | 软目标，不能破坏合法结果或使其失败 |

侧对话建议把冒险等级改为目标等级或允许区间，以减少无解来源。这是待定的配置语义变更，不能在实现时默认采用，也不能据此宣称现有狭窄硬等级带已经得到成功保证。

## 温度配置建议

用户已明确温度等级可配置、温度邻接为软约束。以下字段位置、范围及默认值是拟议接口，需要随正式实现同步配置文档。

```json
{
  "biomes": {
    "terrain_rules": {
      "minecraft:desert": {
        "allowed_terrain": ["plains", "plateau"],
        "max_height": 112,
        "temperature_level": 10
      }
    }
  }
}
```

建议使用整数 `0～10`：0 极寒、5 温和、10 炎热。必须群系、填充群系和结构承载群系共用同一个群系 ID 的温度设置。未配置温度时建议使用 5，保持旧配置可加载；默认配置显式补齐各群系的温度等级。缺省值不能依赖不稳定的容器遍历或未知模组实现。

温度是规划元数据，不参与 `allows` 等地形合法性判断，不修改 Minecraft 群系原有的温度、降雪或结冰属性。温差过大始终允许存在；字段类型错误和超出定义范围则属于配置格式错误。

若把温度放在 `terrain_rules` 中，还需允许仅设置温度的条目，并为缺省的 `allowed_terrain` 明确定义“所有模板”的语义；严格解析、规范化 JSON、缓存输入哈希和旧配置兼容测试必须同步修改。

### 邻接代价

建议在固定的宏观区域邻接图上计算：

`温度代价 = Σ（宏观接壤长度 × 温度等级差²）`

它鼓励雪地、针叶林、温带森林、热带草原、沙漠之间形成较缓和的温度变化。初始化时优先选择温度接近的合法邻居；最低面积满足后，再用有限的位置调整和边界交换改善代价。

接壤长度在固定尺度的宏观图上统计，不能直接使用每个附属斑块的细碎周长，否则优化会因交错边界较长而把它们拉直。宏观聚合方法和优化权重需要实测确定，作为固定版本参数记录。

## 实施顺序与验收

| 阶段 | 具体交付 | 完成条件 |
| --- | --- | --- |
| A：计时与索引 | 分阶段耗时、查询计数、最终单元兼容索引 | 索引与逐格查询一致；保留 r11 三个种子的回归结果 |
| B：联合面积分配 | 配额分配、出生/结构预留接入、新归属持久化 | 最低面积及上限、互斥、地形硬限制全部成立；失败有具体诊断 |
| C：温度与边界优化 | 温度配置、宏观邻接代价、有限交换 | 温度改善不丢失必须群系，不越过地形限制，不消除斑块过渡 |
| D：容量预留契约 | 预留与一次地形生成衔接、证书检查 | 在侵蚀、水文及最终模板分类之后仍能兑现预留；明确等级和结构保证范围 |

各阶段分别计时海岸、侵蚀、水文、成本图、索引、面积分配与软优化，记录总耗时和峰值内存。以相同环境、相同配置和种子比较 r11；冷热计划缓存分开统计，不提前承诺秒级完成。

固定回归种子至少包括 `4126649097427443736`、`345705185492107788` 和 `7331`；另增加预先固定的多种子集合、合法区域容量争用、出生区靠近禁用地形和结构只剩唯一合法位置的案例。

温度验收比较关闭与开启软优化时的宏观温差代价，同时检查实际斑块数量、过渡宽度及直线边界情况。必须包含无法消除冷热接壤的输入，证明它仍返回合法结果。多种子通过是回归证据，不能替代成功保证所需的构造证明。

正式替换归属持久化方式时，应升级相应计划格式或实现缓存版本，并提供清晰的新世界/已有区块兼容说明。现有 r11 修复版仍是此改造完成前的可用基线。
