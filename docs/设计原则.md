# 设计原则

[文档总览](../README.md) · 下一步：[生成流程](生成流程候选.md)

本文定义第一版的产品语义与范围，并已按后续确认的决定对齐：冒险等级为软偏好（r14）、温度类型为硬条件（r28）、面积下界与必需群系缺席按 r29 语义、湿度按填充池修正为保留的显式策略。作者字段见[配置说明](配置说明.md)，粗细地形见[区域模板算法](粗细地形生成算法.md)，算法和数值由对应专题维护；设计确定不表示功能已经实现。

<a id="goal"></a>

## 1．项目目标与规划边界

让整合包作者按自己的冒险意图，编排现有生物群系和结构。作者表达身份、等级、面积、数量及间距，规划器联合求解布局，运行时兑现同一份计划。

核心只做宏观规划，保留探索随机性。通行难度依据粗地形，忽略精细地形的局部通行偏差；不检查群系首次接触顺序、路线提前穿越高等级群系或玩家实际通路。明确的出生安全和结构承载要求仍须成立。

已有存档修改配置由玩家自行承担风险，第一版不设计迁移、兼容或配置变更保护机制。

<a id="concepts"></a>

## 2．核心概念

| 概念 | 含义 |
|---|---|
| 地形类型 | 平原、丘陵等高度形态；与 Minecraft 群系 ID 分开表达，同一形态可承载不同群系 |
| 群系身份 | 原版或模组注册的群系 ID；能解析 ID 不等于表层、植被和水体兼容已验证 |
| 群系地块 `patch_id` | 一次具体的群系出现，具有独立归属和面积；同 ID 可以有多片 |
| 群系种子点 | 地块的规划起点和冒险成本评估位置，通常在中心部分，但不必是几何中心 |
| 结构实例 `instance_id` | 一座确定的结构；宏观按入口选点，实际还需检查完整占地与保护范围 |
| 结构原点 | 适配器定义的局部坐标原点；入口和结构内出生点均相对此点并随旋转变换 |
| 结构入口 | 评估结构到达成本和散落布局的位置，例如城堡门或地牢入口 |
| 玩家出生点 | 玩家脚底的实际放置位置；与结构入口分别记录 |
| 物理占地 / 群系保护范围 | 分别用于三维冲突检查和水平群系承载检查，地下结构尤其不能混用 |
| 到达成本 / 结构间距 | 前者衡量粗地形通行难度；后者是同 ID 入口的水平欧氏距离 |

这些概念用于现有群系、结构及地块，不另引入“冒险区域”配置层。

<a id="world"></a>

## 3．大陆与出生

第一版只修改主世界，在以 `(x=0,z=0)` 为中心的有限单块大陆内安排冒险内容。配置半径是最大圆形包络，海岸向内起伏且保留中心区域；大陆外使用海洋。具体几何保证与形状限制见[海岸算法](海岸轮廓生成算法.md)。

<a id="spawn"></a>

### 出生安排

玩家出生在大陆中心附近。作者可指定出生群系、出生结构，或同时指定二者；同时指定时须身份兼容。

仅指定群系，由程序选取安全地面；指定结构，必须给出结构内相对出生坐标，实际位置严格遵守原点和旋转变换。出生群系沿用统一地块面积规则，不设置专用面积字段。出生需求如何复用或创建地块，完整定义在[出生配置](配置说明.md#spawn)。

顺序必须是：预留出生条件 → 确定出生实例及规划位置 → 建立成本图 → 联合编排 → 复查实际出生一致性。更换出生候选必须重建相应成本图。

<a id="progression"></a>

## 4．冒险等级与到达成本

群系和结构共用整数等级 `0～10`：0 对应出生端，10 对应海岸代表成本。种子点与入口使用同一套等级区间，联合排序并相互约束。自 r14 起等级是**位置软偏好**：它决定候选的优先次序，不划分互斥区间，也不要求不同等级生成彼此不同的跨度要求；同等级的多个对象共用同一处软偏好，但各自的数量与地块归属仍按独立条目计算。

“近”取决于到达成本：山脉阻隔可使直线相近的位置变远，平缓河谷可使连接更容易。“从内到外”表示累计通行成本提高，不表示同心圆环。海岸成本取可达样本的中位数，不要求所有海边成本相同，也不附加等级 10 必须紧贴岸线的几何约束。目标与容差的完整公式见[共同等级区间](群系种子与结构位置选择算法.md#level-cost)。

<a id="arrival-cost"></a>

### 成本计算的边界

到达成本是从规划出生点到目标、在粗地形允许路线中最低的累计路段成本。路段按沿途坡度、水平长度与水体条件累计，不用模板固定难度或起终点净高差替代。

采用粗高度网格、8 邻接与二叉堆 Dijkstra，一次求得所有可达节点的最低成本；不可达为无穷大，后续候选直接查询。上下坡分别计价。相邻节点之间直接查询同一宏观高度函数，沿途分段累计，不用端点插值代替；同一相邻对首次采样后复用双向费用及通行状态。非网格位置通过合法短连接接入，不跨障碍插值。公式与精度见[通行成本契约](生成器参数与执行约定.md#cost-model)。

群系成本评估到种子点，结构成本评估到入口，群系边界和真实探索路线不参加等级顺序检查。主动修改粗高度或通行条件后必须整图重算；只改标签或未影响粗表示的细节沿用原图，详见[失效与重算](生成流程候选.md#cost-recalculation)。

<a id="biome-categories"></a>

## 5．群系需求与面积

| 来源 | 出现和统计规则 |
|---|---|
| 显式必须群系 `biomes.required` | 每条恰好一片独立地块；重复 ID 甚至相同条目也不合并抵销 |
| 结构承载需求 | 每个实际实例需要兼容地块，可共用或新建；仅约束承载该实例的一片 |
| 隐含出生群系需求 | 按出生配置规则复用或创建等级 0 地块，使用公共面积语义 |
| 填充群系 `biomes.filler` | 补齐剩余大陆；不保证每个 ID 出现，不设置等级或面积上下界 |

面积上下界约束每片必须安排的地块，包括结构需求创建的承载地块。结构保护范围、连接种子与保护目标所需的空间均计入；内陆河湖不扣除。

自 r29 起 `area.min` 是**优先争取的有效陆地面积**，不是硬下界：环境限制（温度带、地形准入、面积上限）或受限搜索不足时，允许降到实际合法面积并在计划中记录；`area.max` 仍是硬上限。同一需求可用多个不相连的**区域**播种并合计面积，四邻接连通只要求每个区域自身连通，不再要求整片地块单一连通；放宽与最终实际面积都由终检记录，不静默发生。地块统计与成本图的 8 邻接分工独立。

填充与必须群系互不继承编排要求。即使同 ID 且相邻，填充也不能计入必须地块面积，不同地块继续按各自 `patch_id` 统计。面积单位、默认值及量化见[公共面积配置](配置说明.md#area)和[最终归属表示](生成器参数与执行约定.md#area-grid)。

温度是**硬条件**（r28）：条目配置的温度类型限定它能在哪些温度带完成，播种、扩张、填充与边界混合都受同一限制，不能跨带完成配额。温度类型缺失或与地形准入冲突时，该条目按上一条的面积语义记录实际结果。

<a id="joint-constraints"></a>

## 6．群系与结构联合求解

群系限制结构落位，结构等级也反向约束承载群系。例如前期丛林神庙需要一片容易到达的丛林；其他丛林地块仍可独立安排在远处，未显式配置的承载群系也可由结构需求补充。

`allowed_biomes.id` 非空时任选一种，空列表取消身份限制但保留面积、等级及其他条件；不回退模组原生群系列表。承载需求使用外层结构等级。字段与适配边界分别见[承载配置](配置说明.md#allowed-biomes)和[结构适配](运行时与结构适配.md#spawn-adapter)。

共用地块时，对群系 ID、面积和温度/地形准入取交集，保留显式必须地块的独立要求。等级不是互斥区间，所以不同等级的对象也可以共用同一处软偏好与地块，只是各自的面积、数量与归属仍按独立条目统计；交集为空只否定该共用方案，应尝试拆分或其他选择。准入相容也仍需空间检查。

先满足结构预留、地块最低面积和必要连接，再尝试增加结构数量、分配额外面积及优化形状。位置、面积目标和承载关系允许回退；总面积足够不代表局部空间可行。详细步骤统一见[联合算法](群系种子与结构位置选择算法.md)。

**湿度与填充池的关系（保留的显式策略）**：自然湿度场按温度与地理计算，随后按当前填充配置可用的湿度类型把数值修正到可用档位，因此更换填充池会改变最终湿度，而不是只改变填充选择。这是已保留并显式化的策略（见[湿度供给修正](湿度梯度与沙滩-r20.md)与[重构规划](重构规划.md)§8），不是自然场的固有性质；要改成“更换填充不影响自然湿度”属于单独的产品决定。

<a id="structure-count"></a>

## 7．结构数量、间距与分布

`count.min/max` 按结构 ID 约束整个存档的数量，出生实例占用其中一个名额，不另加一座。实际安排的实例才提出承载需求；受控 ID 须禁止计划外生成，跨区块的一座只计一次。数量上下界不代表均匀随机抽数，也不要求达到上界。

同 ID 的 `spacing.min` 约束任意两座入口的水平距离下界；`spacing.max` 约束整组能用不超过该距离的边连通。它不要求最远两座彼此接近，也不保证大陆覆盖或真实道路。完整字段与特殊数量语义见[结构配置](配置说明.md#structures)。

<a id="scattered-placement"></a>

### 散落分布

第一版仅提供 `scattered`。所有参与实例共同形成总体均匀、带自然扰动的布局，包含固定出生实例和确定数量后的重复实例；不按结构 ID 各自独立分布，不要求规则网格或每种群系分得相同数量。

均匀性是软目标，服从身份、等级、数量、间距、承载和占地等硬约束。优化修改必须重新检查硬约束，失败保留已有合法布局。第一版无独立密度字段；接近惩罚和空缺评分见[散落参数](生成器参数与执行约定.md#scatter-profile)。

<a id="modules"></a>

## 8．核心、扩展与失败边界

核心模组负责基本地形生成、出生安排与群系结构编排，可独立工作。Planner 决定宏观布局，地形模板与 Noise 实现局部形态，运行时执行固定计划。

道路、沿路放置及道路难度修正归道路扩展，核心无需了解道路规则。补充结构、补充群系和群系美化可作为其他扩展；公共接口留待后续设计。外围环境第一版使用海洋，沙漠、虚空等另行讨论。

明确配置矛盾须指出相关规则；抽样失败、空间贪心失败和预算耗尽不能冒充无解。`count`、`spacing`、`area.max`、身份与温度准入都不得放宽。

面积下界与“必需对象必须出现”按 r29 的语义执行：完全没有合法位置时，普通群系允许缺席并记录实际面积 0，面积下界允许降到实际合法面积——两者都必须进入计划记录与终检结果，不能静默发生；出生点与必需结构仍必须有真实合法落点，否则按失败处理。失败类别见[终止与诊断](群系种子与结构位置选择算法.md#termination)，未选型事项见[待讨论问题](待讨论问题.md)。
