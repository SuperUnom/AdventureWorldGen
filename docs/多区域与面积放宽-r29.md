# r29 多区域与面积放宽

## 原因与新行为

r28 的最低面积依然是硬成功条件：即使温度、地形都合法，只要单块连续区域装不下最低面积，播种就失败；后续生长也只会清空不足的区域再重新选址，没有真正降低面积要求。

崩溃报告的种子是 `473008176757882763`。该种子的尖峭山峰合法区域面积分别为 28016、6160、32 平方方块，没有单块满足默认的 32768。

按用户确认，r29 改为：

1. 优先在有界候选集中寻找能满足最低面积的连续区域。
2. 找不到时保留合法小区域，不中止播种；普通群系完全没有合法位置时记录零供给并允许缺席。
3. 初轮生长不足时，保留已取得的全部归属，再在其他合法区域补种。同一需求使用一个稀疏归属集合，允许包含多个不相连区域，面积合计。
4. 补种按 16、8、4 格候选目录推进，每条需求最多 64 个种子；目录在该需求的多轮补种间复用，避免重复全域搜索。
5. 搜索不足或空间耗尽后接受实际面积，在日志中记录需求、实际面积与种子数。后续目标竞争仍可继续扩大面积，配置的 `max` 保持硬上限。

温度、湿度、地形、高度、水体和危险区域的限制保持有效。放宽面积不会让雪坡进入配置外的中温带。出生必须有合法核心，必要结构仍需可放下完整占地、保护范围和入口的合法位置；降低群系最低面积不等于取消这些条件。

## 查询、校验与缓存

联合规划不再因低于配置最低面积拒绝结果。边界混合保护配置 `min` 与实际分配面积的较小值，运行时保存阶段使用相同规则，避免面积回退后又被旧校验拦住。

有效面积统计直接遍历稀疏归属单元，避免多区域跨度较大时扫描中间整片空白范围。归属仍使用已有 `CellMask` / `plan-v2` 保存；内部规划修订更新为 `multi-region-area-r29`。

默认 JSON 的面积数值未改写，仍表达用户希望争取的规模。语义说明已更新到 `docs/配置说明.md`。

## 本轮验证

仅六项定向检查（约 0.72 秒）和一次崩溃种子的离线规划，没有启动游戏、运行多种子批量测试或完整测试套件。

- 两个分离区域合计满足面积，且不会占用中间的非法区域；重复结果一致。
- 总合法面积小于最低要求时，保留实际归属并通过联合规划校验。
- 无相应温度供给时允许普通群系缺席，不能跨温度带补面积。
- r28 的温度约束、填充边界和配置覆盖检查继续通过。

崩溃种子离线运行约 72.7 秒，成功完成 READY 保存，共 38 个规划地块、1 个结构。此次使用现有 `PlanningBenchmark` 的固定金字塔测试占地，未验证 Minecraft 真实结构模板的放置。

该次规划中，尖峭山峰实际面积 16928，冰封山峰 17280，各使用 3 个生长种子；雪林没有合法种子，记录面积 0。面积不足不会再触发本次崩溃。日志位于 `neoforge/build/reports/r29-area-relaxation/planning.log`。
