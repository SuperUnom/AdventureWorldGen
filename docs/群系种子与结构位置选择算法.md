## 1．方法与职责

采用“候选点离散化＋群系与结构联合搜索＋最低面积可行性检查＋整体布局优化”。群系种子点、结构入口、承载关系和最低占地一起求解。选点时检查是否放得下；失败时允许更换位置、旋转结构、拆分承载地块或回退之前的选择。

总体顺序为：

`展开需求实例 → 固定出生候选 → 建立成本图与等级区间 → 建立候选承载关系及位置候选 → 联合搜索并分配最低面积 → 在数量上界内尝试增加实例 → 合法扩张额外面积 → 优化散落布局 → 填充与细化 → 最终复查 → 保存`

本算法负责宏观规划。到达成本只使用粗地形，不检查群系首次接触顺序、路线是否提前穿过高等级群系，也不增加精细通道或实际路线的逐段验证。群系形状扩张使用四邻接，成本图寻路使用八邻接，二者职责独立。

## 2．输入、实例与确定性

输入包括世界种子、粗地形、出生要求、必须群系需求、结构需求，以及已解析的每条必须群系一片需求、结构数量上下界与间距、适配信息和内部参数。大陆范围与海岸采样来自[海岸轮廓算法](海岸轮廓生成算法.md)。

群系地块是某个群系的一次具体出现，以稳定的 `patch_id` 区分；同 ID 可以有多个地块，地块不必与地形区域一一对应。

<a id="instance-count"></a>

### 2.1 结构数量与必需实例

结构条目使用必填的 `count.min/max`，均为非负整数且 `min ≤ max`；同一结构 ID 不允许重复条目。对结构 `s`：

```text
spawn_s = 1（被选作出生结构）或 0（其他结构）
n_min,s = max(count.min,s, spawn_s)
n_max,s = count.max,s
n_min,s ≤ n_s ≤ n_max,s
```

若 `n_min,s > n_max,s`，报告静态配置冲突。先展开 `n_min,s` 个必需实例，其中出生实例占一个名额。稳定实例 ID 使用结构 ID 与序号，出生实例固定使用该结构的第一个序号，尝试增加或撤销其他实例时不重排已有 ID。

`1～1` 恰好一个；`2～5` 优先联合安排两个，可在后续增加；`0～0` 不产生实例或承载需求。`scattered` 只规定共同分布方式。每条 `biomes.required` 恰好对应一片独立必须地块，即使 ID 和等级相同也不合并；结构是否共用承载地块由搜索决定，最终新增承载地块数随共用关系变化。

下界是数量搜索的起点，不是提前断言无解的依据。尤其配置 `spacing.max` 时，更多实例可能连接分离区域；下界方案失败后按[数量向量规则](生成器参数与执行约定.md#search-profile)继续尝试范围内数量，预算累计。找到任意范围内合法方案后才进入可选增量阶段。

### 2.2 搜索数据与稳定标识

群系地块记录：

```text
patch_id
候选群系 ID 集合
适用的冒险等级要求及需求来源
面积下界、面积上界
允许地形条件
承载的结构实例
```

结构实例记录：

```text
instance_id
结构 ID、冒险等级、数量配置来源、是否为必需或可选实例
允许的承载群系及面积范围
合法旋转
相对入口坐标；出生实例另含相对出生坐标
物理占地、需要保护的群系覆盖范围
其他明确的放置条件
```

物理占地与需要保持群系身份的覆盖范围分别记录。地下结构不默认要求整个水平投影属于同一群系，由结构适配信息明确覆盖要求。允许地形、占地等属于已解析的需求或适配信息，这些数据通过适配接口取得，不增加作者 JSON 字段。

随机派生、稳定顺序及完整输入的复现条件统一遵守[确定性契约](生成器参数与执行约定.md#profile)。

字段缺省与校验规则见[作者配置](配置说明.md)。结构采用[适配契约](运行时与结构适配.md#spawn-adapter)准备完整部件和预留范围，不能在实际生成时再随机改变占地。

## 3．出生候选与成本图

在[出生中心范围](生成器参数与执行约定.md#coast-profile)内，按[出生候选阶段](运行时与结构适配.md#spawn-adapter)枚举位置。仅指定群系时枚举安全地面；指定结构时枚举合法原点和适配器支持的水平四向旋转，出生结构等级必须为 0。[出生契约](运行时与结构适配.md#spawn-adapter)规定高度、安全检查和失败修复。

设结构原点为 `o`，旋转变换为 `R`，相对出生点和入口分别为 `r_spawn`、`r_entrance`：

```text
p_spawn    = o + R · r_spawn
p_entrance = o + R · r_entrance
```

检查出生与承载条件后，暂时固定一个出生方案。玩家出生位置与结构入口分别记录；两者都要随旋转变换。

将出生位置作为额外源节点，以经过粗地形通行检查的短连接接入周围网格节点。使用粗高度网格、八邻接与二叉最小堆 Dijkstra，从出生位置一次计算全部可达网格节点的最低累计成本 `C(v)`；不可达节点记为无穷大。建图和求解遵守[通行成本与单源求解](生成器参数与执行约定.md#cost-model)，有向坡度成本按方向分别计算，均须非负。

非网格位置 `p` 通过同样经过检查的短连接查询：

```text
C(p) = min { C(v) + w(v, p) | v 属于 p 的合法接入邻点 N(p) }
```

没有合法可达接入点时返回无穷大；出生位置本身的成本为 0。查询不允许直接对隔着障碍的成本值做插值，也不为每个目标重新寻路。接入使用所在网格面向外一圈最多 16 个节点；成本网格从 16 方块起，可细化到 8，连接按最多 8 方块微段直接查询宏观高度函数，累计水平长度与有向坡度代价，并检查水体及对角避角；同版本相邻对首次采样生成双向费用，后续复用[边缓存](生成器参数与执行约定.md#edge-cache)。[完整规则](生成器参数与执行约定.md#cost-model)统一用于建图和查询。

一次联合搜索固定出生位置。后续无法找到布局时，外层可以更换出生候选，并重新计算成本图。

## 4．共同等级区间

沿[最终海岸折线](海岸轮廓生成算法.md#coast-samples)按近似等弧长采样，通过陆侧合法短连接筛选可达样本，以到达成本中位数作为海岸参考。记等级为 `L`，允许偏差系数为 `ε`：

```text
C10 = median { C(p) | p 为可达海岸采样点 }
Δ   = C10 / 10
TL  = L · Δ
IL  = [max(0, (L - ε) · Δ), (L + ε) · Δ]
0 < ε < 0.5，L 为 0～10 的整数
```

群系种子点和结构入口使用相同区间，等级为 `L` 的评估点必须满足 `C(p) ∈ IL`。容差与海岸采样间距由[海岸 profile](生成器参数与执行约定.md#coast-profile)固定并保存。

相邻等级区间不重叠。对 `Lq > Lp` 的两个对象：

```text
C(q) - C(p) ≥ (Lq - Lp - 2ε) · Δ > 0
```

因此等级同时约束顺序与跨度，`1、2、3` 和 `1、5、9` 产生不同的成本跨度。同等级对象没有额外先后次序，在各自区间内通过空间条件和布局评分安排。

等级 10 采用海岸的代表成本，不表示所有海岸成本相同，也不保证所有同等成本位置紧贴海岸；这里不增加沿海几何位置硬约束。区间上端可以超过 `C10`，不将全大陆成本截断为 `C10`。没有可达海岸或 `C10 ≤ 0` 时，该粗地形与出生方案无效。

等级 0 的区间容纳出生附近的群系种子与结构入口，不要求它们和玩家出生坐标重合；固定出生实例仍须通过适用的入口和种子等级检查。

## 5．可回退的承载关系

每个结构可以选择兼容的已有地块，也可以提出新承载地块。不同显式必须条目对应独立地块，不能合并抵销条目数量；多个结构可以共用其中一片。新地块只需从允许列表选择一种群系。空列表视为当前生成器支持的全部群系集合，不回退到模组原生允许列表，面积约束仍参与求解。

同一地块承担多个需求时取交集：

```text
B_allowed = 所有适用的群系 ID 集合的交集
A_min     = max(各需求面积下界)
A_max     = min(各需求面积上界)
I_patch   = 所有作用于该种子点的等级区间的交集
```

当前采用保守共用策略：显式必须群系的种子等级保留，结构提出的承载需求使用结构等级；纯结构生成的地块也按结构等级检查种子。按当前不重叠区间，不同等级需求不能共用同一个种子点，改为不同地块。同 ID 的其他地块不受影响。

`B_allowed` 或 `I_patch` 为空，或 `A_min > A_max`，表示该共用方案不可行。先尝试拆分或其他承载选择，不据此直接宣布整个配置冲突。同等级且交集非空也不保证能共用，仍须通过占地与空间分配检查。

该策略比允许一片大群系承载多个阶段的方案更保守，当前按本策略实现；后续如调整跨等级共用语义，应同步修改等级交集规则和相关文档。

## 6．位置候选与兼容关系

### 6.1 群系种子候选

从规划网格陆地点生成种子候选，过滤不可达、等级区间不符及明确地形条件不符的位置，再检查附近允许连通空间是否可能满足最低面积。初步空间检查仅用于排除明显不可行位置，不代替多地块共同分配。

### 6.2 结构候选

在有限规划域中枚举合法原点和旋转，确定相应高度与实际入口、物理占地、群系保护范围。按入口检查等级，按占地检查承载条件，并排除与固定出生实例等已确定预留的冲突。原点步长按[候选阶段](生成器参数与执行约定.md#search-profile)细化，高度和完整部件按[结构适配契约](运行时与结构适配.md#spawn-adapter)确定。

### 6.3 候选兼容关系

为结构候选记录可配合的承载地块与种子候选，至少检查：

- 群系身份满足要求，种子与入口各自满足等级要求。
- 结构所需群系保护范围能够归入该地块。
- 种子与保护范围能够通过允许格子形成连通地块，所需面积不超过上界。
- 明确的结构占地、承载条件与已有预留不冲突。

种子与入口可以不同，不要求重合。这里只建立潜在兼容关系，最终仍须把其他地块竞争的空间一同纳入检查。

按成本与空间分层保留候选，再逐步扩大至本阶段完整域；不能只保留最高分位置。分配、结构、出生精度及各次原始枚举预算统一遵守[候选阶段表](生成器参数与执行约定.md#search-profile)。当前域未穷尽不能报告该域无解。

## 7．有界联合回溯

搜索状态同时保存承载关系、群系 ID、种子位置、结构原点与旋转、预留范围、面积分配状态和未决候选集合。不得先不可逆地固定地块关系或位置，再把放不下的问题交给后续阶段。

每一步选择剩余合法候选最少的变量；数量相同时优先处理占地较大、允许群系较少或影响对象较多的变量。等级已通过共同区间落实，无须机械地按等级从低到高锁定位置。

尝试一个候选后立即传播限制：删除冲突占地，更新承载地块交集，删除无法配合的种子或结构候选，并检查局部空间容量。任一必需对象候选为空或已能证明空间不足，撤销本次选择，恢复被修改的状态，再尝试其他候选。

候选尝试顺序综合考虑接近等级目标、保留他人候选数量、局部空间余量和总体分散程度。评分只决定搜索次序，不抵消硬约束；权重、归一化及同分顺序已在[候选参数](生成器参数与执行约定.md#search-profile)固定。

面积分配作为搜索的一部分：部分状态先用便宜检查剪枝；位置与承载方案形成后，必须取得满足最低需求的实际空间分配，并通过同 ID 间距检查，才能作为可行解。面积分配失败时允许回退位置和承载关系。

`spacing.min` 是同 ID 任意两座入口的平面距离下界；`spacing.max` 要求同 ID 实例可由不超过该长度的边连通。部分图尚不连通不能直接剪枝，须考虑其余实例和数量分支。对需要整平的结构候选，按[有限支撑修复](生成器参数与执行约定.md#terrain-repair)建立新粗地形版本，整图更新成本与全部约束后再继续；不能用旧区间接受新布局。

## 8．最低面积的共同分配

对地块 `b`，令 `Xb` 为最终取得的规划格子集合，`Rb` 为所承载结构需要保护的群系范围并集。必须同时满足：

```text
seed_b ∈ Xb
Rb ⊆ Xb
A_min,b ≤ area(Xb) ≤ A_max,b
Xb ∩ Xc = 空集，b ≠ c
Xb 的所有格子满足该地块允许地形条件
Xb 保持四邻接连通
```

连接种子与各保护范围所需的格子计入地块面积；这里的连接是群系空间的宏观连通，不是要求生成道路或验证玩家精细路线。必要连接和保护范围可能使面积超过下界，只要不超过上界即可。

单独检查每个种子附近面积足够不能证明整体可行，因为多个地块可能依赖同一片空地。实际检查分两层：

1. 先检查保护范围冲突、允许连通分量容量、各地块剩余可用面积等必要条件，排除明显失败状态。
2. 通过后进行多地块四邻接扩张，实际取得满足上述全部约束的格子分配。

从种子所在格子开始扩张，每次只加入与已有地块共边且符合硬约束的格子。结构保护范围是必须纳入的目标；尚未连接到种子的保护范围不能作为已经满足连通性的独立起点，连接过程也不得突破面积上界或侵占其他地块的预留。

扩张优先处理“剩余可取得面积相对缺口最紧张”的地块；缺口除了最低面积，还包括尚未纳入的保护范围和必要连接。每加入一个格子，更新其他地块的可用空间；若造成其他地块必然无法满足最低需求，立即撤销。

格子的尝试次序可以偏好距种子较近、填补凹口、地形适合并受低频扰动影响的位置；评分只决定搜索次序，不排除其他合法分配。玩家到达成本约束冒险进度，扩张评分分配群系空间，不将二者当作同一个量。

贪心扩张失败后，尝试其他边界格子分配。必要时回退先前扩张选择；仍无法取得可行分配，则向位置搜索反馈相关地块、预留与瓶颈格子，尝试更换种子、结构位置或承载关系。一次贪心失败不是无解证明。

只有完整穷尽当前离散域内适用的格子分配与位置、承载选择，才能声明该域无解；为提速省略分支的扩张策略不具备这一结论资格。

面积采用平方方块，分配格子边长按 16、8、4 细化，最终归属为完整 4×4 格子，每格面积 16。每级下界取 `ceil(A_min/a)`、上界取 `floor(A_max/a)`，不能向外取整放宽。必须地块的整个单元须在大陆内，最终面积直接由同一归属图统计。粗级无法表达先细分；最终级共用交集为空则尝试拆分，不将精度问题自动当作作者配置矛盾。

输入面积范围要求宽度至少 256，交集后不再次施加该宽度限制。剩余容量与缺口、形状分数及紧张优先调度采用[已确定公式](生成器参数与执行约定.md#shape-profile)，最终量化约定见[面积与网格](生成器参数与执行约定.md#area-grid)。

<a id="optimization"></a>

## 9．可选数量、额外面积与散落分布优化

<a id="optional-count"></a>

### 9.1 在数量上界内尝试增加实例

先保存满足所有有效数量下界和最低面积的可行布局，再按世界种子派生的稳定条目顺序轮流尝试增加一座，跳过已到上界的条目。轮流处理避免单个结构先独占全部剩余空间，但不承诺各结构得到相同比例的额外名额。

每次增加都调用同一套候选生成、约束传播、承载选择与最低面积联合搜索：允许移动已安排的非出生实例、种子及调整承载关系；出生实例保持固定，所有既有必需数量与已接受实例数量均保留。新增实例提出自己的承载需求，不能只找空点而忽略地块面积。

新增方案通过全部当前硬约束时替换已保存方案；失败或本次预算耗尽则恢复原方案。撤销新增实例时一并撤销它独占的承载需求与地块，不影响其他实例或显式必须群系的需求。完整一轮无增加、全部到上界或可选阶段总预算耗尽时停止。调度和操作预算作为可复现内部参数保存；最多 128 次增加尝试，单次及全局状态上限见[预算表](生成器参数与执行约定.md#search-profile)。

这是有界的增量策略，不寻找数量总和的全局最大值，也不保证上下界内数量均匀随机。一次增加失败可能在不同出生方案或布局中成功，但已有范围内方案足以满足数量配置，无须因此继续外层搜索。

可选阶段的预算与必需搜索、最终复查预算分开。可选阶段耗尽可以进入后续阶段并最终返回成功；尚未找到满足下界的方案时耗尽预算，仍返回 `SEARCH_BUDGET_EXHAUSTED`。保留增量前方案作为后续细化修复失败时的回退候选，但任何回退方案仍须通过最终检查。

<a id="biome-shape"></a>

### 9.2 额外面积与形状

获得满足全部最低需求的布局后，各地块轮流继续扩张。扩张偏好使用距种子距离、边界紧凑程度、地形偏好和世界种子驱动的低频扰动。每次仍维护面积上界、四邻接连通、种子归属与结构保护范围。

额外面积不足时停留在合法面积即可，不要求达到早期随机挑选的目标。种子一般位于地块中心部分，但不强制等于最终几何中心。额外面积采用有效区间中点为软目标，按当前面积与软目标比例轮流增长；权重和停止条件见[范围参数](生成器参数与执行约定.md#shape-profile)。

额外面积与散落优化完成后，在最终归属阶段无损细分到 4 格子，再通过单格转让及一对格子交换修整锯齿、凹口和狭长突出部分；交换须同时维护双方的面积范围、四邻接连通、种子归属和结构保护范围。移动种子或结构入口时重新检查相应成本区间。保存已经通过检查的可行布局，修改失败时撤销，优化预算耗尽时保留已有合法结果。

受扰动 Voronoi 仅可作为形状初始化参考，不能代替最低面积共同求解；当前主方法仍为受约束扩张与回退，不增加一个独立的 Voronoi 范围分配阶段。

### 9.3 所有散落结构共同优化

所有 `scattered` 实例共同参与，包括固定出生结构；使用入口的水平投影，不按结构 ID 分开评分。接近惩罚减少扎堆，空缺评分减少大片空白；采样域、归一化、权重、空集合处理和完整公式统一见[散落参数](生成器参数与执行约定.md#scatter-profile)。

此处平面距离用于判断散落形态，冒险等级继续使用到达成本。均匀性是软目标，不能绕过允许群系、等级和承载条件；低频扰动作用于候选偏好和评分，不能在优化结束后任意移动坐标。

尝试移动结构、交换候选、移动种子或调整共用关系，每次重新检查受影响的硬约束与面积分配。保留已经通过检查的可行布局，优化失败或预算耗尽时可以返回它；不会为了改善分布丢失已有可行解。

<a id="validation"></a>

## 10．填充、复查与保存

剩余空间用作者的填充群系补齐。填充地块与必须地块保存不同归属标识，即使群系 ID 相同且相邻，也不合并面积统计。填充池必填非空，按 256 方块分区播种，在合法 ID 中等概率选择，通过四邻接多源扩张分配；无覆盖分量继续补种子。算法与失败行为见[填充规则](生成器参数与执行约定.md#filler)。

最终统一检查：

- 所有需求已被满足；每条显式必须群系保留独立地块，每个结构 ID 的计划实例总数处于 `count.min/max` 内，出生实例计入且只计一次。
- 同 ID 入口间距下界成立，配置了最大间距时对应阈值图连通；不增加全大陆覆盖或实际路线要求。
- 实际出生位置与规划一致，明确的出生安全及结构承载条件成立。
- 群系种子与结构入口仍在各自共同等级区间内。
- 承载群系身份、适用需求交集、结构占地和保护范围成立。
- 地块面积、四邻接连通、种子归属成立，地块之间不重叠。
- 填充没有覆盖已保护范围、没有计入必须地块面积；细化后仍按最终归属表示复查面积。

边界细化与实际生成使用同一份最终归属表示，不能分别按规划格子和另一套未经复查的生成边界判断面积。边界细化或优化使硬约束失败时，撤销有问题的修改或进行有界修复；未经最终检查的结果不能保存为成功计划。

若规划主动修改粗地形高度、路段长度或通行连接，整张成本图重算，并更新海岸参考、等级区间和候选合法性，复查所有对象。只改标签或没有影响粗地形表示的细节则沿用成本图，不增加精细地形通行反馈。

输出已检查的布局与需求来源，交由[不可变计划契约](运行时与结构适配.md#persistence)保存；文件字段、校验、发布和部件去重在该处定义。规划成功仅说明布局通过检查，运行时必须按同一计划实际放置，不重复消耗名额，也不能用生成失败实例充数。实际区块和第三方兼容仍须按[验收矩阵](实施与验收指南.md#acceptance)验证。

<a id="termination"></a>

## 11．预算、回退与失败分类

分别设置候选扩展轮数、必需搜索节点数、可选增量节点数、面积分配节点数和优化次数预算，优先使用确定性的操作次数保证可复现。诊断记录相关需求 ID、候选阶段、地形版本、成本区间、空间瓶颈和预算使用情况。

失败处理顺序为：回退面积分配 → 更换相关位置或旋转 → 调整承载关系 → 扩大候选集 → 更换出生方案。第一版不启用通用宏观地形修复，只允许受预算限制的出生与结构支撑整平；提交新粗地形版本后必须重算成本并更新所有约束。具体升降幅度、回滚和细节恢复见[修复边界](生成器参数与执行约定.md#terrain-repair)。

| 返回结果 | 含义 |
|---|---|
| `SUCCESS` | 得到通过全部最终检查的布局 |
| `CONFIG_CONFLICT` | 找到能够明确证明的配置矛盾，指出相关条目 |
| `NO_SOLUTION_IN_DOMAIN` | 完整穷尽所声明的有限离散域后无解；记录该域、出生候选、地形和精度范围 |
| `SEARCH_BUDGET_EXHAUSTED` | 预算耗尽，尚不能判断是否有解，或最终检查尚未完成 |
| `RESOURCE_LIMIT` | 节点数、样本数或估算内存超过本 profile 上限 |
| `UNSUPPORTED_CONTENT` | 缺少必要群系或结构适配能力，不能按契约保证结果 |

单个共用关系失败、抽样失败、一次贪心扩张失败与预算耗尽，都不能称为配置冲突。`NO_SOLUTION_IN_DOMAIN` 也不证明其他网格精度、未搜索的出生点或不同粗地形不存在解。当前精度不适用作为具体原因记录在域与诊断中。

## 12．控制流程与复杂度

以下为设计伪代码，不是已实现接口：

```text
plan(input):
    spec = 按配置契约解析、静态校验并预检适配能力(input)
    if 已证明配置矛盾: return CONFIG_CONFLICT
    if 缺少适配能力: return UNSUPPORTED_CONTENT

    for terrainPrecision in [16, 8]:
        for candidateStage in 配套的分配、原点与出生精度阶段:
            for spawn in 本阶段确定性出生候选序列:
                terrain = 用固定区域模板和水体描述准备本版本粗采样及出生支撑(terrainPrecision, spawn)
                costMap = Dijkstra(terrain, spawn, 本地形版本的按需双向边缓存)
                if 没有有效海岸成本参考: continue
                levelIntervals = 建立共同等级区间(costMap)

                for counts in 从有效下界起按额外数量递增的有限数量向量:
                    requests = 展开独立必须地块与本数量向量的结构实例
                    for sampleLimit in [256, 1024, 4096, 本阶段完整域]:
                        domains = 生成候选并传播硬约束(requests)
                        result = 联合回溯(承载、种子、结构、面积、间距, domains)
                        # 提交支撑整平时重算成本并更新全部变量域
                        if result 得到可行布局:
                            result = 在数量上界内有界尝试增加实例(result)
                            result = 合法扩张额外面积(result)
                            result = 优化所有散落结构的共同布局(result)
                            result = 无损细分到4格子、填充并修整合法边界(result)
                            if 独立最终检查通过(result):
                                return 原子保存并返回 SUCCESS(result)
                            撤销细节修复或退回增量前方案重做后续阶段
                            if 回退或修复后通过独立最终检查:
                                return 原子保存并返回 SUCCESS(result)
                            # 仍失败时继续其他分支，保留预算检查
                        if 任一必需操作预算耗尽: return SEARCH_BUDGET_EXHAUSTED
                        if 资源超限: return RESOURCE_LIMIT

    if 完整穷尽声明域内数量、出生、位置、承载及面积分配:
        return NO_SOLUTION_IN_DOMAIN(完整域与诊断)
    return SEARCH_BUDGET_EXHAUSTED(未穷尽范围与计数器)
```

`N` 个粗网格节点的成本图时间为 `O(N log N)`、内存为 `O(N)`。联合放置与连通面积分配最坏搜索量为指数级；不能把 Dijkstra 的复杂度当成完整算法复杂度。

实际开销通过候选过滤、约束传播、必要条件剪枝、局部回退和预算控制。算法保证成功结果满足所定义的约束，不承诺任意配置都能快速找到布局，也不承诺散落评分达到全局最优。
