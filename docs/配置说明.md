[返回文档总览](../README.md) · [设计原则](设计原则.md) · [内部参数与执行约定](生成器参数与执行约定.md)

状态：第一版作者配置契约和严格解析器均已实现。本文完整定义字段、缺省值和静态校验；[完整示例](#example)使用虚构 `example:*` ID，不代表内容已经适配。

作者配置身份、等级、面积、数量与间距，生成器负责成本图、位置、形状及搜索。冒险等级为 `0～10` 的整数，出生端为 0、海岸代表成本为 10；r14 起等级是位置偏好，不是硬区间；到达成本和评分参数由生成器计算。面积、地形、身份、数量和物理约束仍为硬条件。

<a id="top-level"></a>

## 1．整体结构与通用校验

| 顶层字段 | JSON 类型 | 必填／缺省 |
|---|---|---|
| `world` | object | 必填，`radius` 必填 |
| `spawn` | object | 必填，至少指定群系或结构 |
| `biomes` | object | 必填，`filler` 必填非空；`required` 缺省为 `[]` |
| `structures` | array of object | 缺省为 `[]`；指定出生结构时必须包含其对应条目 |

未知字段、重复 JSON 对象键、`null`、类型不符、非有限数值均报配置错误，不静默忽略或替换。整数不接受布尔值或带小数部分的数值；数值须能由实现无损解析到相应整数或有限 binary64 类型。所有 ID 使用完整的 `命名空间:名称`，并在开始规划前解析；不存在的 ID 是错误，缺少必要适配能力报告 `UNSUPPORTED_CONTENT`。

作者数组中不同必须群系条目分别保留；填充列表与承载 ID 列表按集合规范化。结构数组同 ID 重复为错误。解析器须先完成静态校验和适配预检，再进入随机候选搜索。

<a id="world"></a>

## 2．`world`：大陆配置

| 字段 | JSON 类型 | 规则 |
|---|---|---|
| `radius` | number | 必填，有限正数，单位为方块；无默认值 |

原点固定 `(0,0)`，半径限定最终不规则大陆的最大延伸；大陆整体缩放到该范围，不通过圆形裁剪生成海岸，也不是等面积半径。外围使用基础海洋 `minecraft:ocean`，不开放外围环境字段。

海岸使用[二维细胞轮廓与多尺度分形细化](海岸轮廓生成算法.md)。第一版不开放幅度、频率、岸带或形状字段，统一使用[海岸参数](生成器参数与执行约定.md#coast-profile)。过小半径不能容纳出生预留时报告不兼容；过大规划域超过资源上限时报告 `RESOURCE_LIMIT`，均不自动改半径。

<a id="spawn"></a>

## 3．`spawn`：出生选择

| 字段 | JSON 类型 | 规则 |
|---|---|---|
| `biome` | string | 可选，玩家出生地块的群系 ID |
| `structure` | object | 可选；存在时 `id` 和 `spawn_point` 都必填 |
| `structure.id` | string | 引用 `structures` 的同 ID 条目，不单独再生成实例 |
| `structure.spawn_point` | array of number，长度 3 | 相对结构原点的玩家脚底坐标 `[x,y,z]`，三个有限数值 |

仅群系出生时省略 `structure`；仅结构出生时省略 `biome`；两者至少有一个。玩家水平位置须在距中心 `min(256,radius/10)` 方块范围内，具体安全及旋转规则见[出生与结构适配](运行时与结构适配.md#spawn-adapter)。

出生结构必须满足 `count.max ≥ 1`。入口与玩家脚底不是同一个点，都须满足出生安全条件；`adventure_level` 可以非零，出生位置优先，保留原配置的软等级目标。

### 3.1 出生群系需求如何取得面积

- 仅指定 `spawn.biome`：优先尝试同 ID 且等级 0 的显式必须地块，按条目顺序尝试并允许回退；其面积按该条公共配置。不存在这类条目时，创建一片隐含等级 0 地块，面积使用公共默认 `min=32768,target=393216，无默认硬上限`。
- 指定结构：使用结构的承载地块；同时指定群系时须满足其非空允许列表，空列表允许该群系。没有指定群系时由承载搜索选择。
- 出生结构可共用兼容的显式等级 0 地块；共用时取面积交集。没有兼容条目时按结构的 `allowed_biomes.area` 新建承载地块，不另外叠加一份默认出生面积。
- 已存在但不能满足空间或交集要求的同 ID 地块不能被静默改写。必要结构的承载群系按独立需求先生成，随后在其中放置结构；仅群系出生已经有显式等级 0 需求时必须从这些候选地块中选择，无法满足则报告搜索失败。

不增加出生专用面积字段。隐含地块使用同一套面积与最终归属规则，有效陆地面积按下节计数。

<a id="required-biomes"></a>

## 4．`biomes`：群系配置

### 4.1 必要群系与填充池

`biomes.required[]` 每条配置提出一个独立必要群系地块，必填 `id`、`adventure_level`（0～10），可选 `area`。重复 ID 保留独立地块、种子和面积统计。`biomes.filler` 是必填非空 ID 数组，重复 ID 去重；是否必要由加入 `required` 表达，填充池本身不保证每个 ID 都出现。

r20 的流程为环境分析 → 需求温度带 → 湿度场 → 出生核心与统一必要种子 → 最低面积竞争生长 → 加入填充种子的持续面积竞争 → 在已规划群系内部放置必要结构 → 剩余区域补全 → 查询层过渡 → 有效面积验证。种子按出生优先、等级升序、同级目标面积降序选择；等级是位置软偏好，不形成硬半径圈。

<a id="area"></a>

### 4.2 公共 `area`：最低、目标和可选上限

| 字段 | 单位 | 规则 |
|---|---|---|
| `min` | 平方方块 | 正整数，必要群系必须达到的有效陆地面积 |
| `target` | 平方方块 | 正整数，期望规模，不能小于 `min`；适宜空间或竞争不足时允许未达到 |
| `max` | 平方方块 | 可选硬上限；省略时无硬上限；必须大于等于 `target` |

省略整个对象使用 `{"min":32768,"target":393216}`。旧的 `{"min":...,"max":...}` 继续接受，`target` 默认为 `max`；旧写法仍要求 `max-min≥256`。新写法允许 `min=target`。显式面积对象必须提供 `min` 以及 `target` 或 `max`，不接受空对象或 `null`。

面积以最终 `4×4` 方块单元统计，向内取整满足硬范围；目标不是硬成功条件。陆地必要群系仅在无水、无危险且满足地形及高度硬限制的单元上生长。**海洋、河流、湖泊均不占用陆地最低面积配额。** 同 ID 的填充地块不抵扣必要地块的配额。

必要主体通过四邻接边缘生长保持连通。达到最低面积后继续接近目标，超过目标后按对数逐渐降低扩张优先级，同时与新加入的填充种子竞争，直到合法边缘被其他群系或自然屏障挡住（显式 `max` 仍是硬上限）；不会用不相邻的合法点拼凑配额。有限次局部重选址仍不能满足最低面积时，规划失败并报告群系、需求与竞争信息。

<a id="filler"></a>

### 4.3 填充和边界混合

默认填充池以开阔温度带景观为主：平原、向日葵平原、草甸、雪原、冰刺平原、积雪山坡、热带草原、沙漠、裸岩山峰，以及只在部分岸段生成的海滩和覆雪海滩；默认必要群系和填充池均不包含风袭群系。山地填充承担平原硬地形限制留下的空地。

填充池保持字符串数组。每个 ID 的 `filler_weight` 等偏好放在下节的 `terrain_rules` 中，必要群系与填充群系共用环境配置。

`biomes.blend_radius` 为 0～32 的整数，单位是**方块**，默认 **4**；0 关闭混合。规划层保留连续归属，查询层 `LocalBiomeBlend` 读取未经混合的归属，在给定半径内以连续噪声选择实际邻近群系；候选必须在当前位置满足硬地形及高度规则。相同种子和坐标可复现，不依赖区块生成顺序。

出生核心与结构保护范围保持稳定。若混合使某片必要群系跌破最低有效面积，只关闭该片的边界混合，再验证；不能静默发布面积不足的计划。地表生成读取与 Minecraft 群系查询相同的结果，不另做地表材料或植被混合。

### 4.4 `biomes.terrain_rules`：环境偏好和硬限制

可选对象，以完整群系 ID 为键。没有配置的 ID 允许全部地形，中温偏好，填充权重 1，无高度限制。

| 字段 | 规则 |
|---|---|
| `allowed_terrain` | 非空数组，`plains`、`hills`、`plateau`、`mountains`；省略允许全部；**硬限制** |
| `allowed_templates` | 可选非空具体配方 ID 数组；省略允许全部；与 `allowed_terrain` 取交集，交集为空或没有启用配方时报错 |
| `landforms` | 可选非空数组：`lowland`、`foothill`、`slope`、`peak`；根据最终高度场的山脉影响、坡度和局部相对高差判定 |
| `min_height` / `max_height` | 可选有限数值，地面高度硬下界／上界，包含边界 |
| `temperatures` | 可选非空对象，以 `very_cold`（非常冷）、`cold`（冷）、`medium`（温和）、`hot`（炎热）为键，值为正有限偏好权重 |
| `humidities` | 可选非空对象，以 `dry`（干）、`medium`（中）、`wet`（湿润）为键，值为正有限权重；列出的类型是允许范围，权重是范围内的软偏好；省略时不限制湿度 |
| `shore_only` | 可选布尔值，默认 `false`；为 `true` 时只允许低缓、间断的河岸、湖岸或海岸，不得向内陆扩张 |
| `temperature_level` | 兼容旧配置的 0～10 整数；缺省 5；未提供 `temperatures` 时，0～1 对应非常冷、2～3 对应冷、4～6 对应温和、7～10 对应炎热 |
| `preferred_min_height` / `preferred_max_height` | 高度软偏好范围，偏离只降低评分 |
| `height_penalty` | 非负有限数值，默认 1；高度偏离惩罚强度 |
| `adventure_level` | 可选 0～10 整数，填充群系的等级偏好；省略时参考同 ID 必要条目 |
| `filler_weight` | 正有限数值，默认 1；作为填充被选中的相对权重 |

```json
"terrain_rules": {
  "minecraft:desert": {
    "allowed_terrain": ["plains", "hills", "plateau"],
    "allowed_templates": ["steppe", "plains", "hills_1", "plateau"],
    "max_height": 112,
    "temperatures": {"hot": 1},
    "humidities": {"dry": 1},
    "preferred_min_height": 68,
    "preferred_max_height": 96,
    "height_penalty": 1.5,
    "adventure_level": 4,
    "filler_weight": 0.8
  },
  "minecraft:forest": {
    "allowed_terrain": ["plains", "hills", "plateau"],
    "temperatures": {"medium": 3, "cold": 1},
    "filler_weight": 2
  }
}
```

温度需求按必要群系目标面积统计，多温度按偏好与合法土地供给的平方根归一分摊，不能重复累计；80% 需求比例与 20% 填充基础比例组合。温度场读取侵蚀与水文之后的同一地形，以坐标趋势、连续噪声、海拔降温及出生修正生成。阈值按可分配陆地校准，并在有限方向候选间比较合法地形供给，必要时做局部温度边界修正。四种温度都按配置作为适宜度：播种和扩张先选偏好温度，再按相邻温度距离回退。温度、湿度、地形和难度场确定后保持不变；搜索回退不改写这些场，也不放宽 `allowed_terrain` 或硬高度范围。

湿度场先于群系种子和填充建立，读取相同的最终高度、水文和温度场。连续区域噪声去除当张大陆的整体偏置后形成干湿渐变，高温蒸发与高海拔使环境偏干，河流、湖泊、湿地和海洋增加周边湿度。湿度值范围为 0～1，低于 0.38 为干，0.38～0.68 为中，其余为湿润；湿度面积由环境决定，不按群系目标面积反向调整。`humidities` 限制同时作用于必要群系、结构承载群系、填充生长、补洞及查询层混合，不会在填充不足时自动放宽；自定义填充池应覆盖所用地形和雪带中的干、中、湿润环境。

默认沙漠为 `"humidities": {"dry": 1}`。河床与近岸湿度下限排除沙漠，因此先生成的河流沿线由其他群系承接，水道保持连通。默认海滩与覆雪海滩都配置 `"shore_only": true` 和中/湿润湿度：距水约 36 格以内、比水面高 0～7 格、非山脉且被连续岸线噪声选中的陆地才参与沙滩分配。高岸和未选中岸段保留其他合法群系，河床仍使用河流群系；默认覆雪海滩优先匹配非常冷温度，普通海滩按自身温度配置参与选择。岸段在群系生长时预留，不在生成结束后覆盖必要群系或结构。只允许岸线的群系不能充当每类地形所需的通用后备。

地形模板当前以 `mountains` 表示山脉，高山可用该模板与硬高度组合限制。填充池须为每种地形提供至少一个无高度硬限制的后备群系。`very_cold` 可以与其他温度类型同时配置；任意群系均可配置非常冷偏好，规划器不检测其原生降雪能力。默认配置将非常冷偏好分配给覆雪群系，这只是默认配置选择。默认针叶林另设高度上限，避免落到原版高海拔雪线以上。

所有偏好参与规范化配置和缓存哈希；新算法的缓存版本已更新，旧布局不会作为新布局直接复用。

<a id="structures"></a>

## 5．`structures[]`：结构编排配置

| 字段 | JSON 类型 | 必填／缺省 |
|---|---|---|
| `id` | string | 必填，同一 ID 只允许一条 |
| `adventure_level` | integer | 必填，`0～10`，无默认值 |
| `count` | object | 必填，两个整数上下界均必填，无默认值 |
| `allowed_biomes` | object | 必填；`id` 必填，`area` 可省略使用公共默认 |
| `placement_mode` | string | 缺省为 `scattered`；第一版只接受此值 |
| `spacing` | object | 可省略，表示最小间距 0、无最大间距 |
| `entrance` | array of number，长度 3 | 必填，相对结构原点的入口 `[x,y,z]`，有限数值，无默认值 |

<a id="structure-count"></a>

### 5.1 `count`：出现数量上下界

`count.min/max` 都是非负整数，`min ≤ max`，实际数量须在包含两端的范围内。数量允许固定值，没有面积范围的最小宽度限制。

| 配置 | 含义 |
|---|---|
| `{"min":1,"max":1}` | 恰好一座，即独特结构 |
| `{"min":2,"max":5}` | 至少两座、至多五座 |
| `{"min":3,"max":3}` | 固定三座 |
| `{"min":0,"max":1}` | 可以不出现，出现时至多一座 |
| `{"min":0,"max":0}` | 不安排，也禁止受控 ID 的原生额外生成 |

按同一结构 ID 在整个存档计数，当前实例均安排在主世界冒险大陆内；不按地块、区块或生成回调重新分配名额。出生实例计入总数且只计一次，有效下界为 `max(count.min,1)`，原上界不变；出生 `0～0` 为冲突。

先尝试有效下界数量，再在上界内增加实例；上界不是必须达到的目标，也不承诺数量均匀随机。启用最大间距后，必需搜索还会尝试更多实例以连接分离区域，不能因下界方案失败直接宣布无解。可选增加失败保留合法方案；未达到有效下界或其他硬约束的方案不算成功。

整个计划的实例数量与当前已加载区块里可见数量不同。实际生成按计划实例 ID 去重、禁止计划外额外生成；生成失败实例不能冒充完成。具体契约与已实现行为见[保存与执行](运行时与结构适配.md#persistence)。

原 `unique` 字段已移除。旧 `unique:true` 改写为 `count:{"min":1,"max":1}`；旧 `unique:false` 须由作者填写上下界，不自动猜测，也不同时接收新旧字段。

### 5.2 结构入口与原点

入口用于到达成本和散落布局，玩家脚底用 `spawn.structure.spawn_point`。两者均相对适配器确定的局部原点，经同一个合法水平旋转变换；原点不默认等于包围盒角点或中心。

第一版只使用适配器支持的 `0°/90°/180°/270°`，无镜像；原点高度、预先固定的完整结构部件、三维占地与群系保护范围由[结构适配契约](运行时与结构适配.md#spawn-adapter)提供。缺少支持即报告不支持，不猜坐标或省略保护范围。

<a id="allowed-biomes"></a>

### 5.3 `allowed_biomes`：承载群系

默认金字塔附带沙漠使用公共默认面积 `min=32768,target=393216`，无单独的小面积硬上限。

对象复用公共群系 `id/area` 语义；区别是 `id` 为列表、不含 `adventure_level`，承载需求使用外层结构等级。它不包含必须条目的出现次数或需求索引。

| 子字段 | JSON 类型 | 规则 |
|---|---|---|
| `id` | array of string | 必填；非空时选一种，显式 `[]` 表示任意受支持群系 |
| `area` | object | 缺省为公共面积 `min=32768,target=393216，无默认硬上限`；显式对象两端必填 |

```json
{
  "id": "example:watchtower",
  "adventure_level": 2,
  "count": { "min": 2, "max": 4 },
  "allowed_biomes": { "id": [] },
  "spacing": { "min": 256, "max": 1600 },
  "entrance": [0, 0, 4]
}
```

此示例使用默认 `scattered` 和默认承载面积。空 ID 列表取消身份限制，但不取消面积、等级、支撑、间距或数量约束；缺少 ID 不等于空列表，缺少整个对象也不能自动变成任意群系。

显式列表覆盖原生群系筛选，空列表从注册且适配支持的大陆群系中选择；保留非群系必要条件。做不到覆盖筛选的适配器须报告不支持，不能回退原生群系列表。列表中多个 ID 不要求各放一座；最终数量为 0 时不额外提出承载需求。

### 5.4 放置模式与间距

`scattered` 面向所有结构共同优化（包含固定出生实例），不是按结构 ID 各生成一套互不影响的分布。均匀性和低频扰动服从硬约束。第一版不开放其他模式或独立密度参数；沿路放置仍归道路扩展。

<a id="spacing"></a>

`spacing` 是可选对象：

| 子字段 | JSON 类型 | 规则 |
|---|---|---|
| `min` | number | 缺省 0，有限非负值；同 ID 任意两座入口水平距离的下界 |
| `max` | number | 缺省无上界，存在时须有限且大于 0，并且 `max ≥ min`；同 ID 连通图的最大边长 |

距离为入口水平投影的欧氏距离，单位为方块；不使用到达成本。`max` 表示这些实例能通过每步不超过该值的边连成一组，等价于其最小生成树最长边受限，不要求最远的两座也在此距离内。它不保证覆盖大陆，也不要求存在道路。0 或 1 个实例时距离规则自然满足，若希望至少两座须填写 `count.min ≥ 2`。

`spacing:{}` 与省略一致；`null` 不表示无上界，直接省略 `max`。不同 ID 没有公共硬间距，但仍遵守物理占地不冲突，并共同参与散落评分。最大间距的搜索衔接见[间距与数量向量](生成器参数与执行约定.md#search-profile)。

<a id="cross-validation"></a>

## 6．字段之间的共同约束

每个必要结构实例都会提出一个独立的必要群系需求，与 `biomes.required` 使用相同的温度统计、等级/面积排序、种子评分、竞争生长、连通性和有效面积校验。其允许 ID 列表表示择一生成，不重复累计需求面积；同 ID 的独立条目仍保持各自配额。先完成全部必要群系布局，再在对应群系中放置必要结构，完整占地、群系保护范围和入口必须落在该群系内。结构适配器不会提前冻结或预留一片矩形群系，放置失败不能覆盖既有群系或静默省略必要结构。

等级不再划分互斥区间；群系锚点和结构候选按连续等级惩罚排序，允许偏离目标。同一位置的软等级偏好不改变独立条目的数量与归属要求。出生结构与出生群系同时指定时须身份兼容，且实际出生与规划一致。

冲突诊断须给出具体 JSON 路径及相关条目。例如等级缺失、面积只填一端、`max-min<256`、结构数量为负、重复结构 ID、`spacing.max<spacing.min`、出生结构上界为 0，以及承载保护范围超过合法面积上界。

`CONFIG_CONFLICT` 仅用于明确静态矛盾。空间放不下可能是搜索域、精度或预算问题；不把抽样失败当作作者配置矛盾。完整失败分类见[预算与诊断](生成器参数与执行约定.md#search-profile)。

## 8．第一版边界

本页作者配置已确定；没有隐含的“以后实现时自行决定”字段。群系形状、海岸、噪声、通行、搜索和评分均使用[内部 profile](生成器参数与执行约定.md)，不加入作者配置。

版本外字段和外围选型统一见[待讨论问题](待讨论问题.md)；新增字段须显式修改契约版本。已有存档改配置不提供迁移或兼容机制。

### 已规划存档读取

r20 将最终温度场（含高程尺度场、阈值和局部修正）、湿度水源距离/水位场、填充网格和边界最低面积保护一起写入 READY 计划。缓存命中直接恢复，不再运行填充、过渡或面积保护计算；配置与算法版本不变时同坐标查询结果一致。旧算法缓存需要一次重新规划，之后再次进入走直接恢复。


### 地形配方参数（r21）

`world.terrain` 为可选对象，省略使用全部默认配方。`composite`、`mountain_ranges` 是独立布尔开关，均默认 `true`。`templates` 以具体配方 ID 为键，未填写的配方和字段继承默认值；因此只填写一个配方不表示关闭其余配方。

| 四大规划分类 | 具体配方 ID |
|---|---|
| `plains` | `steppe`、`plains` |
| `hills` | `hills_1`、`hills_2`、`dales`、`torridonian` |
| `plateau` | `plateau`、`badlands` |
| `mountains` | `mountains_1`、`mountains_2`、`mountains_3`、`volcano` |

每个配方支持 `weight`（0～10000，0 禁用）、`horizontal_scale`（0.25～8）、`vertical_amplitude`（大于 0、至多 220 方块）、`detail_strength`（0～2）。至少启用一个配方。火山默认权重 0.6，为有火山口、无熔岩管或危险覆盖的休眠形态。水平尺度和细节强度为倍率，垂直幅度直接使用方块单位。极大幅度会在生成前降低基础海拔，为建筑高度和侵蚀预留余量。

```json
"world": {
  "radius": 3000,
  "terrain": {
    "composite": true,
    "mountain_ranges": true,
    "templates": {
      "hills_1": {"weight": 16, "horizontal_scale": 1, "vertical_amplitude": 52, "detail_strength": 1},
      "volcano": {"weight": 0.6, "horizontal_scale": 1, "vertical_amplitude": 180, "detail_strength": 1}
    }
  }
}
```

配方权重控制合法候选集合内的相对选择概率，不承诺有限大陆的每个种子出现所有配方。复合区的主、副配方都必须符合群系的分类和具体配方限制。每个启用配方必须至少有一个不限制高度、地貌部位且非 `shore_only` 的填充候选。配置拒绝未知键、空集合、非有限数值、越界值和空交集；规范化输出包括所有配方默认参数，并参与缓存指纹。

温度和湿度规划会检查具体配方、复合成分和地貌部位的填充供给。例如没有合法雪地填充的恶地不会划入雪地带，没有干燥填充的森林复合区会使用可满足配置的湿度区间。该步骤发生在群系分配之前，不改变地形、水体或群系自身的硬限制。详细移植边界与验收见 [r21 地形配方与山脉](地形配方与山脉-r21.md)。
