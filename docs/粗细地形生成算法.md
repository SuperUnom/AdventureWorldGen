# 粗细地形生成算法

r21 修订：四大分类下接入 12 套具体配方，先规划连续山脉和区域容量，再生成统一高度场。具体实现、默认映射和证据见[地形配方与山脉](地形配方与山脉-r21.md)。

状态：区域模板、连续宏观地形和 `ftf-hydrology-adapted-v2` 均已实现并通过性能与运行时验收，内部版本为 `planner-v2`。本文定义地形生成步骤和粗细阶段的数据关系；全部数值集中在地形参数表。

## 1．职责与整体顺序

粗地形阶段已经确定地形区域、模板、主要山体与谷地，并形成可查询的宏观高度函数。粗网格只是这个函数的采样和规划索引，不把每格变成同一高度的平台，也不把丘陵幅度压小。精细阶段在更密的坐标查询同一宏观函数，再增加受限细节。

```text
种子、作者半径与出生要求
→ 固定海岸和中心保留区
→ 连续山脉走廊、区域容量与合法配方交集
→ 地形区域中心、主副配方、基础海拔和幅度
→ 区域宏观高度及共同边界混合
→ 岸带和海床
→ 冻结侵蚀增量
→ 主要河谷和水体
→ 最终地貌部位测量（不修改高度）
→ 出生候选及已批准的支撑补丁
→ 16 方块粗采样，必要时 8 方块
→ 沿边查询宏观函数，计算有向成本图
→ 联合编排与独立检查
→ 保存地形描述及布局
→ 运行时逐区块查询宏观高度并增加局部细节
```

地形区域与生物群系地块分别管理：前者指定高度模板，后者在联合编排时确定最终群系 ID 和面积。区域 ID 不等于 `patch_id`，不要求一一对应。联合编排只允许已有契约中的有限支撑整平，不能为了选点成功重新抽模板或改变宏观山体。

本方案借鉴 FreeTerraForged 的扰动细胞分区、区域模板与共享边界地形，具体参考[源码手册第 4 节](FreeTerraForged_地形生成移植算法手册.md#ref-4)。当前使用本项目噪声内核及适配后的全部 12 套配方，不承诺与参考源码逐点复现，不自动采用 UPLIFT 分级水位。

## 2．先固定地形区域

在大陆包络外保留区域查询缓冲，建立世界对齐的方格布点网格，每格一个中心。对整数格坐标 `(i,j)`：

```text
s(i,j) = L × (i+0.5, j+0.5) + (jitter_x, jitter_z)
q(p)   = p + warp(p)
```

`L`、偏移上限与扰动参数见[地形 profile](生成器参数与执行约定.md#terrain-profile)。两个偏移轴、两个扰动轴使用独立稳定随机键。区域 ID 使用整数格坐标，中心位置固定并保存。

生成中心时，首先覆盖最大圆形包络加扰动幅度和两个布点间距的缓冲域。用未枚举格子的可能中心包围盒距离下界，验证它们不可能成为查询域内最近或次近中心；不能证明时继续扩展外环，受资源预算限制。不要只保留中心落在大陆内部的区域，否则沿海分区会变形。

对 `q(p)` 使用精确最近邻查询，取得最近和次近中心的欧氏距离 `d1,d2`。可用空间索引及包围盒下界剪枝，不假定固定 3×3 搜索始终充分。距离同分按稳定区域 ID 决定；中心不会重合，因此 `d2>0`。

每个中心按固定权重累计区间选择一个模板，区域种子由世界种子与区域 ID 派生。`q(0,0)` 所属区域固定使用平原模板，其他区域按权重选择；这不保证整个出生中心范围都属于平原，具体出生候选仍须检查安全与承载。没有合法出生候选时报告相应搜索失败，不悄悄压平整片大陆。

初始区域布局形成后，模板及随机键在一次计划中固定。原有搜索预算没有包含无限重抽整片地形的尝试，不增加这种隐式兜底。

## 3．连续宏观高度函数

### 3.1 噪声与模板

四大规划分类只用于兼容性判断，具体配方见[配置说明](配置说明.md#地形配方参数r21)。配方使用梯度噪声、Cubic、反馈 Ridge/Billow、Worley 峰体、嵌套坐标扰动和不同阶地算子；形状归一化至 `[0,1]`，局部细节为有界独立分量。

```text
区域粗高度 = 基础海拔 + 拟合幅度 × 具体模板形状
区域细节   = 拟合幅度 × 细节强度 × 局部细节噪声
```

基础海拔在内部相对海面表示，落地方块高度统一加上海面 64。复合区按较低频选择场混合普通配方，各配方保留自己的水平尺度、相对幅度和细节参数。所有预留需求允许集合取交集；主、副配方都在交集内。山脉使用独立的冻结折线路径与宽度场，并在地形生成前决定山地区域，边缘以连续影响值减弱为山麓。

容量预留先寻找天然符合整个高度包络的区域，再换用允许配方或调整基础海拔、幅度；狭窄低海拔需求使用独立低地区域，并利用既有海岸侵蚀衰减计算更小的安全包络。候选失败就尝试其他位置，耗尽后给出请求、群系、缺失面积、配方与高度拒绝数量。禁止对已经生成的整片高度用需求上限／下限裁切。最终水文和群系精确单元检查仍是面积证据。

### 3.2 区域边界混合

r21 直接混合近邻模板，避免所有区域边缘都回落至同一低地而形成规则隆起：

```text
w_i = Π[j≠i] smooth(clamp(1 - max(0, d_i - d_j) / transitionWidth(i,j)))
Hregion(p) = Σ w_i × Htemplate(i,p) / Σ w_i
```

各距离在扰动坐标中计算。邻域使用中心格附近 5×5 个候选；边界两侧连续交换权重；按邻区两两计算，避免三岔交界处最近区域切换造成跳变。相同配方过渡 96，山地组合 200，台地／恶地组合 88，其余组合 144；局部细节独立使用 32 的窄过渡。群系兼容性在 48 的窄交错带内选择实际配方，不把整段坡面变成大范围混杂区。

主要丘陵和山脊属于此宏观函数，采样稀疏不会主动降低其振幅。区域边界高度连续不意味着所有位置曲率平滑，实际坡度仍按函数采样计算。

## 4．海岸、水体与宏观地形版本

把 `Hregion` 作为陆侧相对高度，按照[岸带公式](海岸轮廓生成算法.md#section-5)接到同一最终海岸折线及海平面。海床侧由受支持的海床高度源提供，海平面与方块量化遵守[海岸契约](生成器参数与执行约定.md#coast-profile)。

主要河流与湖泊在成本图前提供固定几何和高度描述：中心线或边界、河床／湖床剖面、河谷影响范围、纵向水位以及汇流关系。由这些数据得到可在任意位置查询的地面、水面、水深和危险状态；河口必须接到既定岸线。主河不能只在少数网格节点标成水，否则窄河会被漏过。

河流、水面、湖泊、湿地、海床和规划期侵蚀统一采用 `ftf-hydrology-adapted-v2`；保留部分以固定提交 golden vectors 验证，替换大陆场、稳定随机键与水体查询的适配部分单独验证本项目约束，不宣称与 FreeTerraForged 世界逐点一致。

宏观查询结果为 `macroSample(p)`：粗地面上表面高度、水面高度、水体类别、危险标记、区域与模板信息。`macroHeight(p)` 是其中的地面高度。输出已经包含海岸、水体切削和批准的支撑补丁；所有查询使用同一不可变地形版本。

## 5．粗采样与到达成本

常规粗采样与成本节点默认间距为 16 方块，必要时进入 8 方块。每节点记录函数采样结果；节点之间仍可直接查询同一宏观函数，不能把格子当成常高块，也不能仅把节点插值当作精确高度。

半径约 3000 方块的包围方形，在 16 方块间距下按面积估算约 14.1 万个节点，实际还要考虑网格对齐与边界缓冲。规划不需要先算约 3600 万个水平位置，更不预先生成全部三维方块。

相邻节点的连接在世界坐标中分成不超过 8 方块的微段，并补入水体／危险／海岸边界交点。在每个采样位置调用 `macroSample`，逐段累计坡度、水平长度与水体费用。端点高度相同但中间凸起的连接，也必须计入爬升和下降成本。

第一次查询相邻节点对时，一次高度采样产生双向费用及可通行状态，随后复用。对角连接复用正交辅助边进行双绕角检查，详见[边成本与缓存契约](生成器参数与执行约定.md#edge-cache)。这里的精细计算止于宏观函数，不读最终方块，也不验证玩家逐方块路线。

有限间距仍可能漏过小于采样尺度的细小起伏，不宣称得到连续曲线的精确积分；明确几何边界通过交点补采样处理。精度不足按既定 16→8 阶段处理，不在失败时任意改变成本模型。

## 6．从宏观函数生成精细地形

每个模板把宏观层和细节层分开保存。细节使用独立噪声键；区域细节也以同一权重 a 混合到公共边界细节，保持区域交界的一致性：

```text
D(p) = (1-a(p)) × Dborder(p) + a(p) × Dtemplate(region_id,p)
Hfinal(p) = macroHeight(p) + M(p) × D(p)
```

基础细节公式、尺度和幅度上限见[地形参数](生成器参数与执行约定.md#terrain-profile)，每个参与混合的细节场均受同一上限约束。权重 `M∈[0,1]` 在出生支撑、入口和结构保护范围内为 0，范围外平滑恢复；海岸带衰减并继续保持既定陆海侧别，河床与湖床保护域内为 0。多个掩膜取乘积，任一保护都生效。内陆水面沿用已保存水位，不添加细节噪声。

对可能改变外海侧别的细节按既有海岸约束限幅；结构支撑只恢复已批准表面，不能生成另一份宏观整平补丁。精细高度随后按宿主约定生成方块、表层和已有群系装饰，真实出生与承载须复查。

区块生成时只计算所需坐标，宏观函数、模板、相位和河网与规划完全一致。不能简单放大粗网格作为最终山体，也不能增加噪声层后重新归一化整个宏观函数；细节层不会重新决定主山体、谷地或河道位置。第一版不在精细阶段额外运行会改变宏观高度的侵蚀；后续若采用这类处理，必须进入规划使用的宏观地形版本。

所有函数使用世界坐标与稳定键，不依赖区块加载顺序。有限细节仍会带来局部通行偏差，按既有宏观边界忽略，不新增精细通行反馈。

<a id="persistence"></a>

## 7．保存与验收

[plan-v2](运行时与结构适配.md#persistence)同时保存地形描述与粗采样数据：区域中心和稳定 ID、模板及版本、参数和种子键、公共与区域噪声内核、最终海岸、水体几何及水位、支撑补丁和细节保护域。仅保存粗高度数组不足以复现宏观函数和精细地形。

粗采样是规划索引和缓存；运行时根据完整描述重建同一可查询函数。函数或必要适配器版本不可解释时报告不支持或读取错误，不回退成粗网格放大。边成本缓存属于派生数据，不持久化。

实现验收应覆盖区域边界与三交点、同种子复现、中心区域选择、丘陵主要高差保持、粗采样与同坐标宏观查询一致、不同区块顺序无接缝、细节幅度与保护掩膜、水体几何命中、边内起伏对费用的影响、缓存调用计数以及地形修改后的失效。具体证据归入[实施验收](实施与验收指南.md#acceptance)。设计完成不代表这些测试已经通过。
