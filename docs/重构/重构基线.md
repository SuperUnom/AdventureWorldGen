```bash
cd neoforge

./gradlew test --offline --no-build-cache --console=plain
```

两点必须注意，否则会得到假的"通过"：

1. **`--no-build-cache` 不可省略。** `:test` 是 `FROM-CACHE` 可缓存的；省略时 Gradle 会直接复用上一次的测试结果，不真正执行测试。本轮一开始就踩过：`cleanTest test` 仍然 `FROM-CACHE`。

### 3.1 端到端计划字节基线（新增）

`neoforge/src/test/java/io/github/luoyan/adventureworldgen/runtime/PlanningBaselineTest.java`

它在**不依赖 Minecraft 注册表与适配器**的前提下复刻 `RuntimePlanner` 的阶段顺序（海岸 → 容量预留 → 区域地形 → 侵蚀 → 水文 → 成本图 → 联合规划 → 计划组装），固定种子与配置，然后冻结三项可对照结果：

| 对照项 | 值 |
|---|---|
| 规范 `plan-v2` 字节 SHA-256 | `60db9c350e163356b58be39437bddc31e1cfde5ef9322994f2763e974421ccfe` |
| 采样字段 SHA-256 | `ce1ac745adc29f185a2867031eb7a8b29de29f895066226014e1211da0a92a0f` |
| 出生点 | `0.5/0.5/0.0` |

固定输入：种子 `0x5EEDBA5E`、`radius=512`、出生群系 `test:plains`、必需群系 `test:forest`（等级 3）、一个必需结构 `test:keep`（等级 4，承载群系 `test:desert`）、填充 `test:plains/test:forest/test:desert`。

采样字段覆盖：地形高度与水面、水体种类、危险地形、地形配方、地貌类型、实心表面、群系归属、结构相交查询（实例 ID／原点／旋转／入口／部件数）、出生点、填充种子数。

同时断言 **READY 重载一致性**：`decode` 后再 `encode` 必须逐字节等于首次编码结果。这条断言直接守住"改类名不得改线格式"。

这些常量是"行为未变"的**证据**，不是可调参数。纯结构调整必须原样复现；确需改变行为时须单列为行为变更并给出自己的验证记录，不能悄悄改这些数字。

## 5．文档冲突表

《设计原则》保留的是第一版产品语义草案，其中若干硬约束表述已被后续实现与《配置说明》覆盖。以下冲突**不阻塞**保留行为的结构调整，但重构时不得按旧表述"恢复"行为。

| # | 主题 | 《设计原则》旧表述 | 现行语义 | 现行出处 |
|---|---|---|---|---|
| 1 | 冒险等级 | §4 把等级描述为跨度要求（"`1、2、3` 和 `1、5、9` 不能生成相同的跨度要求"）；§6 称"当前不同等级不共用一个种子点"，读起来像互斥区间 | r14 起等级只是位置软偏好，不划分互斥区间；同一位置的软等级偏好不改变独立条目的数量与归属 | 《配置说明》第 11、246 行 |
| 2 | 面积下界 | §5"面积上下界约束每片必须安排的地块"，暗示 `min` 为硬约束 | r29 起 `min` 是"优先争取的有效陆地面积"，环境受限或有界搜索不足时允许降低到实际合法面积；`max` 仍是硬上限 | 《配置说明》第 78、86、88 行 |
| 3 | 必需群系是否必须出现 | §8"不能跳过必需对象""不得静默放宽等级、面积、数量或间距" | r29 明确"普通群系完全没有合法位置时允许缺席，记录实际面积 0"；出生与必需结构仍须有真实合法落点 | 《配置说明》第 86、88 行 |
| 4 | 地块连通性 | §5"最终地块保持四邻接连通" | r29 允许同一需求在多个不相连区域播种并合计面积，放宽只涉及最低面积与单区域连通性 | 《配置说明》第 86 行 |
| 5 | 温度是否为硬条件 | 《设计原则》只把面积、身份、数量、间距列为硬条件，未把温度列入 | r28 起配置温度类型是**硬**允许范围，不能跨带完成配额 | 《配置说明》第 143 行 |
| 6 | 湿度是否受填充池影响 | 《设计原则》未定义湿度与填充池的关系 | 实现按当前填充池可用湿度类型修正湿度值（保留既有行为，规划默认不删除，改为显式策略） | `planner/HumidityPlan.computeValue` |

处理方式（对应《重构规划》§7）：以对应变更记录、已确认决定与当前代码共同核对，不能仅凭代码现状或文件时间自动决定产品语义。第 6 项与《重构规划》§8 的"需单独决策事项"一致，本轮保留行为。

**2026-09-11 结清（用户确认）**：《设计原则》已按上表的现行语义改写——第 1、4 项按 r14 的软等级表述，第 2、3 项按 r29 的面积与缺席语义，第 5 项写明温度类型是硬条件（r28），第 6 项写明湿度按填充池修正属于**保留的显式策略**。上表保留为历史对照，不再是待解决的冲突。

## 6．旧 READY 样本

本机当前有 **44 份** `plan-v2` READY 样本，全部位于 `.gitignore` 排除的运行目录，**不受版本控制**：

```text
neoforge/run*/**/adventureworldgen/plans/adventureworldgen_default/{manifest.json,plan.json.gz,READY}
neoforge/run-production-server/world-r3-objectgraph/...
neoforge/run-production-server/world-r4-random-seed-evidence/...
```

`manifest.json` 只有 4 个字段：`format` / `input_sha256` / `payload_sha256` / `profile`。

对照抽样结果：

| 样本 | 载入 `hydrology` | 是否可被当前版本复用 |
|---|---|---|
| `run-r33-ocean-caves/testcompanion-plan` | `ftf-hydrology-adapted-v2` | 仅当 `input_sha256` 命中当前实现修订 |
| `run-gametest/testcompanion-plan` | `ftf-hydrology-adapted-v2` | 同上 |
| `run/world` | `ftf-hydrology-adapted-v1` | 否，水文版本门禁直接拒绝 |

该列的 `v1`/`v2` 是**每个旧样本自身记录的版本**，不是当前实现：当前实现固定为 `plan/PlanVersions.HYDROLOGY`（`ftf-hydrology-adapted-v2`）。本表是 2026-09-10 的历史抽样记录，引用时请连同日期一起引用，当前版本另见[粗细地形生成算法](../粗细地形生成算法.md)与[配置说明](../配置说明.md)。

关键结论：**存档复用的实际门禁是 `input_sha256`，不是字段名或类名。** 该哈希包含 `implementation=<实现修订>`，所以跨实现修订的旧样本本来就会重新规划。因此：

- Java 包／类改名**不会**破坏这些样本的载入路径（它们已经被哈希门禁拦下）。
- 但同一实现修订内的**线格式**必须保持不变，否则 READY 会以不同字节重新写出，破坏"重载不重新规划"。这正是 3.1 的 round-trip 断言要守住的。
- 这些样本不被版本控制，`./gradlew clean` 或删除 `run-*/` 会永久丢失。若后续阶段需要长期对照，必须先把选定样本复制进受控测试资源，而不是依赖运行目录。
