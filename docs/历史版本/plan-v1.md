## 1．出生、结构坐标与适配契约

### 1.1 出生候选与安全

出生候选以世界对齐 16 方块格点在中心范围内枚举，后续阶段细化为 8、4；先按距中心距离，再按种子键排序。仅群系出生时，使用格点对应方块中心的安全脚底位置；结构出生时用本阶段出生步长枚举合法原点，而非强制玩家坐标落在格点上；只保留旋转后的相对出生点落在中心范围内的候选。

每个候选预检：玩家碰撞盒宽 0.6、高 1.8 方块，在指定脚底位置上有支撑、盒内无碰撞与流体，脚下非危险方块；3×3 邻域脚底支撑高差不超过 1 方块。最终生成后仅在出生点及明确的结构支撑／入口范围复查这些条件，不增加精细通路检查。

仅群系出生允许在同一水平坐标把脚底 y 更新到同版本确定的安全地面；若与规划 y 不同，必须回到出生候选阶段重算并复查，不能保存前悄悄移动玩家。结构内出生点必须严格保持 `o+R·spawn_point`；若精细化破坏安全条件，最多一次撤销该范围的细节修改并恢复预留，仍失败则换候选。无自动平移、寻附近安全点或无限挖空兜底。

### 1.2 第一版结构接口

下面是本项目拟实现的接口职责，不是已经存在的 Minecraft API 名称：

| 接口 | 必须提供的结果 |
|---|---|
| `describe(structureId)` | 适配器版本、支持群系能力、合法旋转、占地／保护范围上界、出生支持能力、是否能阻止原生额外生成 |
| `prepare(instanceId, originXZ, rotation, terrain, seed)` | 固定原点 y、完整且确定的结构部件计划、三维物理占地、群系保护单元、入口接入高度、支撑与危险条件 |
| `validatePrepared(prepared, terrain, biomeQuery)` | 原生非群系条件、物理支撑、玩家入口和群系承载要求；返回明确原因 |
| `placeChunk(prepared, chunkKey, transaction)` | 仅生成已保存且与该区块相交的部件，幂等提交；不再次随机决定建筑大小 |

> 上表的 `placeChunk` 属历史设计。自 P4.3 起 `StructureAdapter` 不再声明 `placeChunk`／`serializePieces`／`PlacementTarget`：适配器只负责冻结部件，放置走 Minecraft 自己的 `StructureStart` 流水线。当前契约见[运行时与结构适配](../运行时与结构适配.md#spawn-adapter)。

原点是适配器定义并保存的结构局部 `(0,0,0)`，不强制取包围盒角点或中心。只使用绕该原点的水平 `0°/90°/180°/270°` 旋转中的适配器支持子集；第一版不使用镜像。入口与出生点均用同一 `o+R·r` 变换。

地表结构原点 y 默认取全部支撑采样点粗地面上表面高度中位数的向下取整，加适配器声明的固定整数局部基底偏移；多解时仅保留这一确定解，不暗中扫描高度。水面结构取适配器声明水体的水面基准；地下结构必须由适配器提供确定深度算法，不能用地表默认值猜测。无法准备完整部件或无法预先界定最终占地的随机拼接结构第一版不支持。

物理占地用于三维冲突检测；群系保护范围是另一份水平覆盖数据，由适配器返回后向外取整到完整 4 格子。地表结构没有专门声明时默认保护完整物理占地水平投影，入口和出生投影也纳入；地下结构必须显式声明其需要的保护范围，不默认使用整座建筑水平投影，缺少声明则不受支持。不同结构的三维占地不可相交，除非属于同一个计划实例的内部部件；不自动允许两个独立实例重叠。

`allowed_biomes.id` 是作者的身份约束。显式列表覆盖原生群系筛选，空列表使用所有注册且经群系适配器声明支持大陆承载的 ID；不把“支持”伪装成原生结构的允许列表。保留原生非群系必要条件。若适配器做不到覆盖群系筛选或抑制额外生成，报告 `UNSUPPORTED_CONTENT`，不能静默回退原生规则或跳过必需结构。

受控结构只在主世界计划中安排。其他维度的地形与生成流程保持现状；若同一受控 ID 可在其他维度额外生成、且无法在不改变其他维度的前提下保证全存档数量，则该适配组合不受支持，启动规划前报告，不将全存档计数偷偷缩成大陆计数。

## 2．保存、执行与数量去重

### 2.1 不可变计划

在新世界第一次生成冒险区块前完成整个大陆计划和最终检查，写入世界目录的 `adventure_world_gen/plan-v1/`：

| 文件 | 内容 |
|---|---|
| `manifest.json` | UTF-8：格式／算法／profile 版本、种子、规范化作者配置、模组和适配器版本、各负载文件（不含 manifest 自身）SHA-256、状态 `READY`、诊断摘要 |
| `coast.json` | 最终折线坐标、海平面与岸带参数 |
| `terrain.json.gz` | 粗高度、水面、危险标记、网格原点／间距／尺寸及已批准支撑补丁；二维数组按 z 行、x 列排序 |
| `biomes.json.gz` | 最终 4 格子归属的逐行游程编码 `[z, xStart, length, patchIndex]`，地块表包含 ID、需求来源、种子与面积 |
| `structures.json.gz` | 每种结构的上下界、最终计划数量；每个实例的原点／旋转／入口／部件计划／占地／保护范围及涉及区块索引 |

JSON 不写 NaN、Infinity；无穷成本用显式不可达标记。整数索引与长度检查溢出，游程不重叠、无遗漏，字节编码与压缩参数固定。压缩使用 gzip，mtime 为 0，无文件名字段；规范 JSON 键排序、无多余空白，文本换行 LF。压缩库版本记录在 profile；校验和以实际文件字节为准。

先写同目录临时计划目录，校验并刷盘后通过同文件系统原子重命名发布；运行时只读取已发布且校验通过的 `READY` 计划。未完成目录不被查询。首次发布完成前不生成受控区块；已存在有效计划不被重新规划覆盖。这个规则用于保持单份计划一致，不提供已有存档改配置迁移或兼容机制。

### 2.2 查询与提交

规划结果对外提供 `biomeAt(x,z)`、`terrainAt(x,z)`、`structuresIntersecting(chunk)` 与 `spawnPosition()`。读取不可变快照，可并发；任何区块生成顺序都查询同一计划，不再次消耗数量名额。

结构逻辑实例 ID 唯一，跨区块部件使用 `(instance_id, piece_id, chunk_key)` 幂等键。适配器把部件方块与其已提交标记纳入同一次区块持久化事务；重试可覆盖同一确定方块，但不能重复创建战利品、实体或额外部件。无法提供幂等语义的结构适配器第一版不受支持。

> 历史设计：适配器提交事务与逐区块幂等键已随 P4.3 一并移除，当前实现见[运行时与结构适配](../运行时与结构适配.md#persistence)。

原生结构候选入口对所有受控 ID 禁止计划外放置，包括 `count.max=0` 的 ID；只有计划执行器持有的实例可以生成。计数以完整计划逻辑实例为准，跨区块的一座只计一次；未访问区块是未物化，不能当作失败。需要生成的部件实际失败时标记 `EXECUTION_FAILED` 并报告，阻止该受控生成事务完成；重试同一实例，不重新抽位置、增加替代实例或降低下界。

首次读取计划核对适配器与格式版本，无法解释就报错；这是正确读取的必要条件，不承诺配置变更或跨版本存档迁移。
