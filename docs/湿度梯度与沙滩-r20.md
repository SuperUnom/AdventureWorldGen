# r20 湿度梯度与间断沙滩

配置字段见[配置说明](配置说明.md#44-biomesterrain_rules环境偏好和硬限制)。本次加入 `humidities`（干／中／湿润及其权重）和 `shore_only`，生产默认配置中每个群系都有湿度偏好，并将海滩、覆雪海滩加入填充池。

温度场完成后，`HumidityPlan` 在最终侵蚀、水文地形上建立湿度场。32 格环境网格内用 8 格间距探测水源，分别冻结淡水与海洋的距离和水位。区域噪声去除大陆整体偏置，温度控制蒸发，高度控制干燥和淡水影响衰减，邻近水源增湿。查询对网格做连续插值，干湿分类直接影响群系选址和生长。

沙漠仅能占有干区。近水湿度下限让河床和近岸由其他群系承接，保持既有河道连续。岸线连续噪声只选中部分低岸，并在必要群系生长前留给海滩填充；高岸、山脉和其余岸段保留其他合法群系。雪带继续隔离覆雪海滩与普通海滩。必要群系、结构承载、填充、补洞、边界混合均使用统一环境限制。

湿度距离、水位、天气偏置和实际比例随 READY 计划冻结。缓存命中无需重新采样地形或运行湿度／填充生长；实现缓存版本更新为 `planner-v2-impl-2026-09-08-r20-humidity-shores-v1`。旧配置省略湿度字段时维持不限制湿度的行为。

## 验证

`./gradlew build --offline` 通过，完整回归共 108 项测试，失败 0 项、跳过 0 项。构建产物为 `neoforge/build/libs/adventureworldgen-0.1.0.jar`，另提供相同内容的 `adventureworldgen-0.1.0-r20.jar`。

新增测试覆盖配置规范化、非法字段、连续性、水源／高度／温度影响、沙漠与河岸隔离、间断沙滩、雪滩分类、必要群系生长，以及无需地形重采样的计划重载。生产存档测试同时检查湿度字段缺失会拒绝加载，并验证湿度查询一致。

默认配置、种子 `7331` 的完整侵蚀—水文—群系审计通过：31 个规划斑块满足最低有效面积和连通性，结构成功落在预先规划的承载群系内；存档直读约 270 毫秒，同坐标群系保持一致。结构使用审计工具的模拟占地，这不是 Minecraft 实际结构或游戏画面验收。

该大陆陆地湿度占比约为干 15.3%、中 58.2%、湿润 26.6%。`HumidityAudit` 对最终查询按 8 格间距检查 173,713 个陆地样点，未发现违反环境限制的群系；其中沙漠 6,576、海滩 5,903、覆雪海滩 2,172。邻近淡水岸段的沙滩／其他群系样点为 5,238／8,924，邻近海岸为 2,926／6,349，确认两类岸线都保留混合景观。这些是该种子的采样统计，不是强制面积比例。

`neoforge/tools/DemandPlannerAudit.java` 现在额外生成 `*-humidity.png`；`neoforge/tools/HumidityAudit.java` 可读取它生成的计划，检查实际群系查询中的湿度限制及岸线混合。
