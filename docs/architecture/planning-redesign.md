# 多核分层规划、自然气候与三维道路改造

本文记录已批准的完整设计和验收契约。实施期间，目标能力不等于已经交付的行为；
当前实现以[规划](../systems/planning.md)、[地形与气候](../systems/terrain.md)、
[道路](../systems/roads.md)及测试证据为准。本文不维护逐提交记录。

## 目标和边界

统一温湿度供给、共享规划底图、群系与结构候选分配、多核调度、动态道路汇合点和山侧栈道。
保留原生结构预检、道路调度检查点及既有工作区修改。规划发生在 READY 前，worldgen 只消费冻结结果。
路网兼顾通行路程与唯一施工量；山路优先缓坡，困难段允许最大纵坡 45°。
不支持任意悬空道路、长跨谷高架、隧道或旧区块重铺。

## 数据流与执行顺序

需求与粗地形容量 → 地形、侵蚀、水文 → 分块环境与自然成本 → 温湿度联合供给 →
群系合法域和区域图 → 群系与结构候选分配 → 原生实例预检 → 三维道路网络 → 终检和冻结。

先保存修改前默认配置和道路回归种子的阶段耗时、失败、操作数及内存指标。
依次建设底图与调度、气候供给、区域分配、三维施工与路网优化，最后集中完成集成和性能对照。
使用全新目录采集首次规划，READY 对照复用相同输入目录，不删除用户存档。

## 共享底图和确定性调度

- 使用世界对齐的 256×256 方块 tile。环境统计 32 方块，候选 16／8 方块，最终群系归属 4 方块，施工局部细化至方块。
- 数值使用原始类型数组，类型使用标签，合法域使用位图，候选和连通关系使用稀疏索引。
  同一自然地形公式是唯一权威；底图不是另一套近似地形。
- 粗层区分合法、非法、未确认。未经保守证明的否定不能排除细层；局部失败不建立全大陆细候选对象目录。
- tile 单任务构建、完成后只读发布。并行计算采样、合法域、评分、局部连通和道路候选；归属抢占、跨块归并和提交使用稳定顺序。
- 工作线程默认保留一个逻辑处理器，受统一工作内存限制。线程数、缓存、批次大小及完成顺序不能改变规范计划。
- 不具备并发契约的 adapter 受控串行调用，原生实例预检保留现有游戏层边界；缓存只复用可重算结果。

## 温湿度联合供给

- 保留连续自然气候的坐标扭曲，移除低处无法进入最冷档的升温与振幅压缩；基准气候覆盖四档，高度只追加降温。
- planner 将展开需求转换为纯供给目标，climate 不依赖 planner 类型。
- 稳定编号的有限候选与平滑校准联合评估温度、湿度、地形、高度。优先出生及必需结构，再比较普通需求面积缺口和自然形状偏差。
- 单独统计低海拔非山地冷区，不能以雪山面积抵扣。无合法低地时诊断不足，不伪造容量。
- 选择和调整在群系分配前完成；宏观场和校准参数冻结，READY 不重新求解。
- 允许集合决定准入，权重只影响偏好；供给不足不能扩大允许集合。

## 群系与结构区域分配

- 静态合法域与动态 ownership 分开；只有完整准入规则相同且 adapter 语义相同才能共享计算。
- 连通区域统计处理供给重叠，不向多个需求重复承诺同一土地。
- 出生和必需结构先取得承载候选，稀缺需求优先，冒险等级保持软评分。
- 在选定区域内生长和落位；失败时更换候选、补种或拆分有冲突的共享承载组，保留来源身份与等级跨度约束。
- 普通群系最低面积放宽语义贯穿容量与分配；出生可用性、必需结构数量、间距及环境仍是硬条件。
- 结构候选参考粗道路连通和成本，真实范围由原生预检导出；planner 不读取 pieces、NBT 或 Minecraft 对象。

## 三维道路和额外节点

- 分开目的地、网络汇合节点和几何控制点。节点候选来自山口、跨河处、缓坡、走廊接近处和已有路段中间。
- 支持节点插入、移动、删除和路段拆分，共享路段只计算一次建设成本，同时惩罚出生到目的地的绕行。
- 道路从出生分量增量生长，少量地形模板与粗二维走廊选择水平轨迹，沿线求解高度；施工失败才局部修补，详见[道路系统](../systems/roads.md)。
- 建造方式包含地面、短桥、山侧栈道；栈道组合斜向爬升、顺逆绕山、折返平台和地面过渡。
- `maximum_grade` 为高差／水平行程，合法上限 1.0，发布默认配置 1.0，显式较小值仍有效。优选坡度 0.35，超出后增加成本。
- 路面可以悬离地表，必须有受限的山侧托梁及局部锚固；支撑距离作为版本化规划参数。
- 全宽验证纵横坡、台阶、转向、净空、支撑和结构避让；连续曲线合法不替代方块通行验证。
- 同一 XZ 可以有多个施工高度区间；异层不自动连接，同层汇合才是路口；栈道下方不整柱填筑。
- 节点和栈道候选并行评估、稳定提交；提交后复核受影响的入口、路口和高程。

## 接口、资源和冻结

- 只读分块底图、合法域、区域图和规划执行上下文分离。上下文仅管理线程、工作内存、取消和进度。
- 气候状态保存宏观场及校准；诊断保存联合供给、放宽和失败分类。
- 道路节点带类型和高度，路段带三维中心线及方式，施工带分层区间、楼梯朝向及支撑构件。
- 多层水平枚举、按高度定位和按区块遍历替代单层假设；同步更新保护、施工、基础列及高度查询。
- 调度批次可以继续，目的地累计硬预算不可补充；可选优化、必需搜索与终检都有界，不按墙钟改变结果。
- 内存紧张先回收可重算数据、降低并发，不自动降精度。真实内存和输出容量仍是硬上限。
- 区分计算未完成、搜索域穷尽、已证实冲突和资源不足；有界搜索失败不声称全空间无解。
- 更新算法与冻结格式身份；影响结果的新输入纳入规范摘要。旧 READY 不冒充新算法结果，不迁移已有区块。

## 验收

- 气候：平坦低地冷区、高山额外降温、温湿交集、恢复、缓存冷热、负坐标及访问顺序。
- 分配：稀缺供给争用、共享组拆分、窄域局部细化、普通面积放宽与必需结构失败。
- 道路：有收益的途中汇合、共享计费、合成陡山栈道、45°上限、折返、异层净空、接坡和不可支撑情形。
- 确定性：1／2／多线程、不同批次和缓存得到相同规范计划；续算不改变结果，不突破硬容量。
- 集成：受影响定向 JUnit、PackageBoundaryTest、输入身份、codec／READY，以及 planning、roads 和相关原生气候 GameTest；跨区块正逆序一致。
- 性能：同输入改造前后阶段耗时、候选、内存、失败原因对照，输出气候图、路网俯视和栈道侧视。客户端观察单独报告。
- 文档运行 `python3 neoforge/tools/check-docs.py`，交付检查 `git diff --check`。Gradle 使用默认缓存，不默认 clean 或重复全量测试。
